# 账号会员与会员功能

## 统一规则

- 用户分为普通用户和会员用户。登录账号在会员有效期内，可使用全部会员功能；Mist 是当前其中一个功能。
- 每条付费或管理员授予的有效权益记录都授予账号会员身份。现有云存储会员自动具备会员身份；历史 Mist 购买记录也按账号会员处理。
- 生效条件为开始时间不晚于当前时间、结束时间晚于当前时间，且记录没有被撤销。到期或退款后，重新汇总其余有效记录；没有剩余有效记录则成为普通用户。
- 功能统一检查登录态、`membership.active` 和有效期。新增会员功能复用 `useMembershipAccess`、`isMembershipActive` 或原生 `CloudMembership::is_active_at`，不增加功能专属购买权限。
- 会员商品同时授予会员功能和商品列出的存储额度。Staging 年度会员提供 5 GB、终身会员提供 10 GB；AI 使用继续按余额扣点。

### 点数商品

点数商品用 `features.credits` 声明额度，不写 `membership`，因此不授予会员身份、不占用存储额度，只赠送点数。

- 发放时机：支付确认（`checkout.completed` 首次、`subscription.paid` 续订）后由 Cloud 写入，客户端不能自行开通；同一笔支付以 Creem 支付引用作幂等键，重放不会重复发放。
- 归属：进「月度」余额桶，`monthly_expires_at` = 该付费周期结束时间；续订把到期时间往后延，不铸成永久点数。
- 扣费顺序：先扣月度桶、再扣永久桶，避免持有永久点数时让月度点数白白过期。
- 退款：确认全额退款后冲回该订单赠送的点数（与会员权益撤销同一路径）。
- 到期结算：周期结束后首次请求时清空过期月度余额；周期中途到期的，未用完部分作废，不退成永久点数。
- 上架只需目录里加一条 `features_json` 含 `credits` 的商品，客户端无需发版（`billing-products.ts::creditsOf` 决定它落在支付弹窗的点数页签）。


商品使用账号会员描述及 `membership: true` 标记，不再销售 Mist 专属权益。会员功能判断不依赖商品 feature flags；历史 `mistTheme` 字段仅为旧订单数据，不参与授权。

## 数据与权限

- `membership.active`：当前账号是否有有效会员记录。
- `membership.startsAt` / `expiresAt`：当前有效会员记录的最早开始和最晚结束时间。
- `membership.storageExpiresAt`：所选有效存储套餐的结束时间，独立于会员期限。
- 存储额度采用当前有效存储记录的最大额度，不叠加重叠套餐。Actor 使用存储到期时间执行上传限制。
- `user_entitlements` 投影分别保存会员日期和 `storage_starts_at` / `storage_expires_at`。
- AI 请求检查有效会员身份，再检查和扣减点数；模型目录可在登录后浏览。
- 只有验签并校验商品、金额、币种、付款状态后的 Cloud 支付确认流程能写入权益；客户端不能自行开通会员。

## 用户交互

1. Mist 始终展示并标记 Member。未登录点击时进入账号登录；普通用户点击时进入会员购买；有效会员可以激活。
2. 登录后创建订单，订单与当前 Flowix 账号绑定。Creem 支付确认后授予账号会员身份。
3. 付款确认、手动刷新、窗口重新聚焦和定时刷新使用共享 Cloud 状态，所有会员功能随状态更新。
4. 到期时客户端按本地时间立即停止会员功能；退款确认后刷新状态撤销资格。请求失败时对应访问检查关闭。
5. 有效会员状态下隐藏整个会员方案与购买卡片模块，暂不提供升级入口。云存储套餐仍可按其购买规则购买。
6. 每个窗口仅同步自己的原生主题，避免新窗口验证期间覆盖其他窗口。启动或未确认会员前使用 Rock。
7. 旧待付款订单先向支付服务确认状态并清理过期记录，再校验当前购买资格，避免旧订单阻塞会员购买。
8. 会员刷新失败时清除原生共享缓存并通知所有窗口；重试期间保持未验证状态，只有成功刷新才恢复资格。相同或更旧的缓存快照不能清除验证错误。
9. 未购买或已到期的存储套餐返回 `STORAGE_PLAN_REQUIRED`，提示购买或续费存储套餐，独立于账号会员身份。
