# 媒体库设计

## 目标与入口

媒体库是在当前笔记本范围内浏览图片和视频的独立工作区。它显示整本笔记本的媒体文件，不随文件树当前目录缩小范围。卡片墙采用不等高瀑布流；图片和视频统一显示缩略图、名称、修改时间和相对路径。点选卡片打开现有媒体预览 surface。

在文件树“新建”菜单中将“媒体库”放在“多维表格”之后。新建时输入视图名称，生成 `<name>.lib.yaml` 并打开它。媒体库配置是一个视图定义，不复制媒体文件，也不创建额外的属性数据库。单文件预览不再显示通用媒体属性编辑器；属性筛选由媒体库视图负责。

## 文件格式

`name.lib.yaml` 使用独立格式标记、版本和稳定 ID。文件名用于展示；内部 `library.id` 不随改名改变。初始视图配置如下：

复制文件造成 `library.id` 重复时，文件树会标记冲突并暂停分组状态修改；可在副本行菜单为所选文件生成新 `library.id`，同时递增 `library.revision`。视图 ID 和配置保留，新 ID 使用独立的默认分组状态。

```yaml
format: flowix.media-library
version: 1
library:
  id: lib_<uuidv7>
  name: 媒体库
  revision: 0
view:
  id: view_<uuidv7>
  layout: waterfall
  kinds: [image, video]
  sort:
    field: created_at
    direction: desc
```

当前 v1 接受 `format`、`version`、`library` 和 `view`。`library` 只接受 `id`、`name`、`revision`；`view` 只接受 `id`、`layout`、`kinds` 和可选的 `sort`。当前排序固定为 `created_at` 倒序。未知字段、无效 ID、重复或无效媒体类型、非法 revision 和不支持的排序配置均拒绝加载，避免保存时静默丢弃配置。名称、时间、资源属性和路径筛选尚未进入当前 v1 文件格式。

配置保存使用原子写入和 revision compare-and-swap。检测到外部编辑时，应用会读取最新文件，将当前操作合并后重试一次；再次冲突则载入最新配置并提示用户重试。

## 媒体目录与索引

继续使用 `<notebook>/.flowix/notebook.db` 中的 `media_resources` 作为媒体身份目录，不在 `.lib.yaml` 复制媒体清单。目录项至少提供：稳定资源 ID、笔记本相对路径、图片/视频类型、文件名、大小、修改时间、首次发现时间、文件指纹和可用的轻量媒体属性。按 `(notebook_id, kind, created_at, id)`、`(notebook_id, relative_path)` 和名称检索建立索引。已有 `created_at` 可直接作为创建时间定义，不将文件系统 birthtime 当作跨平台保证。

列表 API 采用游标分页，数据库端执行资源类型条件，按创建时间和资源 ID 倒序稳定分页；单页默认 60 项，上限 120 项。游标使用最后一个排序键与资源 ID 构成，避免偏移分页在同步变更时重复或漏项。缩略图独立按需获取，不随列表返回原图或视频字节。修改时间/文件指纹构成缩略图缓存键；视频首帧生成沿用已有预览缓存。

目前资源目录的全量 reconcile 在启动/文件管理变更路径中更新，UI 不扫描并打开每个文件。媒体库列表消费此目录并按文件变更事件刷新当前页；目录批量变化时重置游标。缩略图懒加载，视口附近最多保留约 3 屏卡片并发解码；栅格图片会在桌面端缩小为 JPEG 预览，原图只在用户打开单项时加载。列表按 48 项游标分页，视图文件不携带媒体路径清单。

## 展示和筛选交互

- 首版工具栏支持图片/视频切换；结果按创建时间倒序。名称、时间、属性和路径筛选，以及可选排序仍待实现。
- 后续增加的筛选条件应显示为可移除的筛选标签，并在空结果时提供清除条件操作。
- 媒体网格使用响应式列宽与 CSS columns 或等效虚拟瀑布组件。实现需保持键盘焦点顺序稳定，卡片尺寸由缩略图宽高比决定并设最大高度。
- 图片缩略图用 `loading=lazy`、解码异步和占位图；视频缩略图用原生预览缓存。不可读文件仍展示文件名和路径。
- 文件路径只显示相对路径，悬停提供完整路径；点击打开对应图片/视频资源。
- 当前视图 YAML 只保存媒体类型和固定排序。没有媒体 ID 数组、缩略图数据或资源属性副本。

## 与现有实现的关系

- 复用 `media_resources` 中的稳定 ID、资源类型、创建/修改时间和指纹；媒体仍以笔记本中的原文件为准。
- 复用文件树的媒体类型判定、`read_image_file` 和 `read_video_preview` 的笔记本路径安全约束，以及视频预览缓存。
- 复用文档列表的游标加载、滚动窗口测量和文件变更事件；后续筛选需下推给目录查询，并将等高卡片布局替换为瀑布流。
- `name.lib.yaml` 按独立 surface 解析，不作为 Markdown 笔记索引，也不进入多维表格目录。新建菜单中与多维表格并列，位于其下方。
- 停用媒体属性面板与自由键值属性写入。旧数据库中的 `properties` 内容先保留作兼容数据，不在首版展示或编辑；移除旧数据需另行制定备份和迁移策略。

## 第一版实现状态

已完成 `.lib.yaml` 模型、创建入口、文件识别、独立媒体库 surface 和全笔记本瀑布流。首版支持全部、图片、视频切换，媒体类型和固定排序配置保存到视图文件；查询使用媒体索引的 SQLite 游标分页，图片和视频预览按需请求。页面从索引按创建时间倒序加载，不复制媒体列表。

名称、时间、路径和元数据筛选仍在后续迭代范围；首版不开放复杂的媒体自定义属性管理。当前文件解析器会拒绝这些尚不支持的字段，不会在打开后覆盖丢失。

分阶段顺序允许先完成浏览和基础筛选，而不阻塞于视频元数据抽取。视频宽高、时长等属性在后台惰性提取、限并发、可重试，不阻塞首屏列表查询。
