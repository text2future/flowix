## 阶段 2：对象模型实现与验收

实现已完成；以下验收动作仍需在双设备环境执行。

这两项分别让云端能表达“笔记本是什么”和“目录存在”。索引配置和文件夹外观属于本机配置，不进入云端；笔记正文和附件仍按 `f/` 路径同步。

1. `m/manifest.json` 是每本笔记本自己的云端名片：稳定 ID、名称、图标、排序和删除墓碑。它让已知笔记本的元数据在设备间一致；不放机器专属的本地路径，也不放笔记清单。删除写墓碑，不立即删 `f/`，以免一次误操作变成不可恢复的数据清空。首次在新设备发现笔记本时，设备仍需为它选择本地目录。
2. 用 `d/{dirPath}.json` 表示目录存在。对象存储没有真实目录，文件路径也无法表达空目录，所以只同步文件时，新设备看不到空目录。目录对象有存在/删除标记；目录删除必须在完整列举且经过确认窗口后才能发布，列表失败或不完整不能作为删除证据。`s/` 继续只负责加速扫描，不负责目录身份。
3. 明确 `f/` 的文件白名单：Markdown 正文、附件和确认为用户数据的文件可同步；`.index.yaml`、集合定义文件、`.flowix` 配置及 `folder_index` 展示属性不上传，也不从云端覆盖。`.flowix/database/` 中的记录正文属于用户数据，可以同步。空目录只同步路径存在/删除，不携带该目录的图标、封面或副标题。
4. 已为 manifest 与目录对象实现本地基线、服务端时间 LWW、删除墓碑及重试；新建、改名、排序、删除和目录变化触发同步。远端状态落本地后刷新笔记本列表/文件树。
5. schema 版本、路径规范化、坏数据处理和幂等写入已实现。双设备验收需覆盖空目录新建与删除、离线后重连、目录列举失败、重复重试、新设备首次绑定，以及索引配置和文件夹外观保持本机隔离。
