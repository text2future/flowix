## 1. 上传链路

- 原生 Webview 的浏览器文件改为 `begin_attachment_upload` → 串行 `append_attachment_upload` → `finish_attachment_upload`，不再将整个文件编码成一个 IPC 字符串。
- 每块解码后最多 256 KiB，文件最多 64 MiB。后端核对所属窗口、偏移、声明总长度、实际解码长度和最终长度；重复、乱序、空块、超长及解码失败会拒绝并销毁该会话。
- 会话持有全应用上传配额，和原生路径导入共享最多两个任务的限制。暂存使用自动清理的临时文件，不把所有块留在内存中。
- 会话创建后最多存活十分钟，后台每三十秒回收；取消、窗口销毁、错误及正常完成都会释放暂存文件和配额。窗口关闭代次校验拒绝旧初始化操作。
- 最终提交重新检查 memo 与 notebook 的归属；上传过程中笔记移动到另一笔记本会拒绝提交，而不是悄悄更换目的地。
- 移除旧 `save_attachment_content` 原生命令及其注册。已核查仓库内调用者；自定义 `saveContent` / `saveFile` 回调不变，非原生宿主仍可使用原有协议。
- 原生路径导入仍使用已有的 1 GiB 单文件限制。

### 后端恢复记录

- 附件落盘前，先将目标相对路径、memo ID、大小、SHA-256 和时间写入所属笔记本 `.flowix/attachment-imports/<UUID>.json`。
- 成功发布附件后更新 `confirmed`。确认写入失败不把已经保存成功的文件伪报为失败；事前记录保留为未确认状态，并记录警告。
- 未确认记录可能对应提交前中断，也可能对应已写入但来不及确认；**不能当作删除依据**。确认记录也不代表编辑器已经插入或保存引用。
- `list_attachment_import_records({ notebookId })` 提供读取接口；最多检查 2000 条目录记录，返回所检查记录中最新的 200 条，遇到错误或截断设置 `incomplete`。不是无限制的全量历史查询。
- 前端原有 localStorage 记录继续保留，用于标识明确知道“保存成功但插入失败”的情况。

### 未覆盖

分块限制发生在应用命令层，不能阻止 Webview/IPC 在反序列化前接收恶意超大请求。最终提交开始后不承诺撤销文件发布。文件与恢复记录不是同一个原子事务；断电持久性、操作系统异常和跨进程路径替换仍需平台验证。附件 SHA-256 当前对暂存文件额外流式读取一次，没有做性能实测。

## 2. 权限与凭据

### 已修复的确定问题

- 插件过去到写产物阶段才检查笔记本目录；现在在创建线程、占用运行名额和启动 Agent **之前**校验工作目录，要求是已注册笔记本的规范化根目录。子目录、相对路径和未注册目录拒绝。
- Codex 适配器显式收到未知权限字符串时，之前落入可写工作区默认值；现在降级只读。未提供权限时原有默认行为保留，不擅自改变产品默认配置。
- 注册、登录、Apple 登录和恢复会话加入认证代次；迟到的认证结果不能覆盖已退出或更新的认证操作。
- 刷新令牌写回同时核对认证代次和原刷新令牌；退出后迟到的刷新不能复活本地会话。迟到的会员信息也不能覆盖新认证状态。
- 退出先清理本地会话、会员、账户及持久凭据，再请求远端退出；本地凭据清理失败仍使内存会话失效，并返回错误。
- 持久化刷新令牌在认证锁下读取当前值，不再把早先认证响应中的旧值直接写回。启动恢复失败仅在当前无会话、磁盘仍是该旧令牌时清理，避免误删新登录凭据。
- SQLite 凭据连接开启 `secure_delete`；Unix 凭据数据库在写入前限制为 0600，设置权限失败不再静默忽略。

### 审计边界

凭据仍是 SQLite 明文存储，不是系统密钥链或加密保险库。`secure_delete` 不等于能擦除历史备份、WAL、文件系统快照或介质残留；Windows ACL 和内存清零未完成。没有核实所有 Agent 运行时的真实沙箱执行效果，也没有全量审计插件安装/更新、外部 CLI 参数和运行中的云同步取消行为。没有查询最新依赖漏洞库，不声称依赖安全。

## 3. 保存与事件

- Core 增加 `MemoSaveReceipt`：内容快照、最终路径、memo 元数据、notebook ID 和内容 revision 在共享写锁内形成；旧保存 API 仍保留兼容包装。
- 普通编辑保存的自动版本创建也在该锁内完成，使用对应内容快照。版本恢复继续在校验阶段备份旧内容，再生成恢复后的 receipt。
- 桌面普通保存和版本恢复统一从 receipt 构建响应和事件，不在发布事件时重新读取另一次保存的内容并赋予错误 revision。
- revision/自动版本保存失败会记录警告；不把已成功写入的文件声称为未写入。receipt 的 revision 可为空，尚未提供完整的部分失败恢复协议。
- 前端合并事件按 notebook + memo 分桶，过滤已观察到的较旧 revision；保留同 revision 的元数据更新；合并派生字段刷新标志；标签操作前先派发相关待处理快照，避免旧快照晚到覆盖标签操作。
- 前端 revision 高水位最多保留 10000 个身份，旧协议无 revision 的事件继续兼容。

### 未覆盖

这不是文件、SQLite、版本文件、搜索索引和事件传输的全局事务。其他写入入口、watcher 观察、跨进程事件、旧协议事件、revision 记录失败及程序崩溃仍可能需要重读和补偿。没有增加持久事件队列或启动重放，没有证明全项目事件全序；不能把普通保存入口的修复推广成所有入口都已统一。

## 4. 附件扫描与恢复边界

- 新增 `scan_attachment_references({ notebookId })` 非破坏性扫描接口：列出目标笔记本附件，在全部注册笔记本已保存的 Markdown/HTML/JSON 文件中搜索已有 asset URL 引用。
- 复用同步模块现有 asset URL 路径解析，不读取附件二进制内容、不写入笔记、不删除或移动附件。
- 包含可读取的历史版本和插件文本产物；遇到路径越界、链接、读取错误、非法 UTF-8、深度或数量/字节数上限，报告 `incomplete`。
- 一次最多 2000 个附件，附件枚举和正文扫描各最多 20000 个条目；单正文最多 2 MiB，正文总量最多 64 MiB，每个附件最多返回 20 个引用位置。全应用最多一个扫描任务。
- 返回 `observedIn` 只是所支持 asset URL 的观察结果，不涵盖所有链接语法。每条记录始终 `safeToDelete: false`，没有引用结果也不授权删除。
- 未保存编辑、撤销栈、动态插件引用、普通相对链接、外部未注册文件仍不在完整覆盖范围。**恢复管理 UI 和自动回收没有实施**；本批只提供后端记录与诊断接口。
