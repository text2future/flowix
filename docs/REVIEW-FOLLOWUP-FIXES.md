# Review 后续修复（2026-09-08）

本轮针对代码复核发现的四项确定问题整改，不代表全项目问题清零。

## 修复范围

1. **云同步身份串用**：请求、刷新重试、同步快照及结果报告绑定认证代次；等待锁后重新校验。登录结果真正安装时再次推进代次，避免认证进行期间启动的旧账号请求借用新令牌。最终文件应用与游标提交在认证代次锁内串行执行；应用失败不推进游标。同步应用回调不得重入认证接口。
2. **旧内容生成新 revision**：读取文件前记录 revision 基线，在 SQLite Immediate 事务内比较基线后提交；过时观察不能覆盖已经记录的新提交。被拒绝的观察只发送 `derivedOnly` 刷新，不重放正文事件，也不记录过时的云同步脏标记。未额外获取文件写锁，避免 watcher 持锁路径重入。
3. **上传任务排队无界**：append 在进入 `spawn_blocking` 前校验会话 UUID、空块与编码长度；append/finish 共用最多四个在途请求名额，超限立即报忙。原有最多两个上传会话限制继续保留。
4. **丢弃旧事件时遗漏派生刷新**：旧 revision 的标签、待办等标记进入独立元数据刷新通道；`derivedOnly` 不推进 revision 高水位，不传给正文订阅者。主窗口注册并清理对应订阅，不重放旧编辑器内容。

## 回归用例与验证

- 新增八个 Rust 测试：上传请求准入一个、条件 revision 提交两个、认证隔离及报告应用五个；扩展已有事件序列化测试。
- 新增四个前端测试场景，覆盖旧事件早于/晚于新事件派发、后端派生通知隔离、订阅释放。
- 仅使用 rustfmt 检查 Rust 语法和格式，以及已有 TypeScript 解析器检查前端语法；不等同于编译或类型检查。
- 按要求未构建、未启动项目、未运行单测、未安装依赖。测试结果仍待执行验证。

## 仍存在的边界

- 条件 revision 提交不等于文件系统原子 CAS；任意外部进程替换文件、删除事件在观察前已过时等场景没有全面解决。
- 文件应用与数据库游标提交没有跨介质回滚；仍无完整事务、持久事件队列和崩溃重放。持锁应用文件可能延迟身份切换。
- 已发送的远端请求不能撤回；部分旧令牌下载可能继续至最终代次校验，但不能转用新账号令牌或应用过时代次报告。
- 命令准入不能限制 Webview/IPC 在命令执行前分配的请求内存。
- 附件自动回收和恢复 UI、全量插件/Agent 权限、凭据加密、平台 ACL 及依赖安全审计仍未完成。
