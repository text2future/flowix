# 文件访问边界加固

各节记录对应批次当时的状态；最新修复与尚未解决的边界见 [静态修复状态](STATIC-REMEDIATION-STATUS.md)。

本轮范围：共享路径范围判定、文件浏览监听、目录列表及创建文件夹的名称校验。

## 修改

- 逐段解析已有路径，先解析符号链接再处理后续 `..`，避免词法归一化与操作系统实际访问目标不一致。
- 拒绝相对路径、悬空或循环链接、不可解析路径及普通文件下的子路径；支持合法的多级待创建路径和授权根目录的链接别名。
- 文件浏览监听复用共享判定，不再以字符串路径前缀直接放行事件。
- 目录列表不返回解析后位于当前浏览目录之外的链接项目；内部链接保持可见。
- 创建文件夹复用文件名称校验，拒绝路径分隔符和父目录名称。

## 回归测试

新增 11 个测试：路径边界 7 个、监听边界 2 个、目录列表 2 个。其中 5 个符号链接测试限定 Unix，避免 Windows 创建符号链接权限造成环境性失败。

本轮仅进行 Rust 格式及语法解析检查，没有构建或运行测试，不代表编译或测试已经通过。

## 未覆盖边界

- 路径校验与实际文件操作仍是分离步骤，不能防止其他进程在两者之间替换目录或链接；完全消除此类竞争需要基于目录句柄的受限文件操作。
- Markdown 后缀授权规则已在后续批次移除，见下节；尚未实现按窗口隔离的访问令牌。
- Windows junction/reparse point 的运行时行为尚未验证；当前使用标准库元数据与 canonicalize 解析。
- 相对路径现在拒绝访问，调用方必须传入绝对路径。

## 后续批次：外部文档授权

- `read_document` 和外部文档读、写、监听不再仅凭 `.md` 或 `.markdown` 后缀放行。
- 允许访问注册笔记本、启用的资料目录，以及原生文件选择或系统/命令行打开时明确授予的单文件路径。
- 单文件授权只保存在本次应用会话内，以规范化路径匹配，不扩展到同目录其他文件；原子保存保留授权，链接改指向另一个文件不继承授权。
- 命令行相对文件路径在可信入口转换为绝对路径；未提供前端可任意授予路径权限的 IPC。
- 新增 5 个授权注册表单测，其中 1 个 Unix 符号链接测试；仅完成静态格式检查，未构建、未运行测试。

兼容性与限制：授权目前在应用会话内共享，不按窗口隔离；重启后外部文件可能需要重新选择或通过系统打开。深链中的文件地址、恢复的标签页、仅由前端传入的路径不自动获得新授权。其他附件、导出及通用文件接口不属于本批次的授权重构范围，不能据此宣称应用已全面隔离文件访问。

## 后续批次：导出及附件另存为

- 文本导出、附件另存为必须使用同一窗口的原生保存对话框选定的准确目标路径，前端不能自行扩大授权到其他文件。
- 每个窗口最多保留一个待用目标，授权一次性消费；再次打开保存对话框和窗口销毁时撤销旧授权。写入失败后需重新选择目标。
- 两类导出共用流式临时文件写入、同步和原子提交，并持有核心跨进程写锁；大附件不整体加载到内存。
- 如果选定时目标不存在，提交使用禁止覆盖模式，保护对话框关闭后其他进程创建的文件。选定已有普通文件允许覆盖并保留权限，链接或目录目标拒绝。
- 新增 10 个回归单测，覆盖无授权、窗口隔离、单次消费、授权撤销、目标竞争、二进制内容、失败清理及 Unix 链接替换。静态格式检查通过，未构建、未运行测试。

限制：已有文件在用户确认覆盖之后被其他程序修改仍可能被覆盖；外部进程替换父目录的 TOCTOU 风险仍存在。附件导入的源文件授权、目标笔记本选择和并发命名尚未在本批次改造。

## 后续批次：附件模块

- 附件导入逻辑拆分为独立存储模块，两种输入（文件流、Base64 字节）复用同一提交路径。
- 显式解析已注册的目标笔记本，不再修改全局当前笔记本；无效 ID 直接报错。未指定 ID 时使用当前笔记本，没有当前笔记本时使用注册的默认笔记本。
- 来源文件必须属于可信目录或明确授权的单文件；原生文件选择和原生拖放事件提供授权，不接受前端自行声明授权。
- 在共享跨进程锁下流式写入临时文件，同步后禁止覆盖提交。重名时保留临时文件、选择下一个名称重试；失败清理临时文件，不留下半成品。
- 文件名跨平台清理，处理 Windows 保留设备名；拒绝附件目录链接逃逸，悬空链接同名项不被覆盖。
- 附件打开及另存为从所有注册笔记本识别来源，不再受全局当前笔记本影响。
- 前端只插入真正持久化成功的附件，批量上传部分失败时保留成功项，不再生成失效卡片或失败项的预览 URL。
- 新增 10 个 Rust 单测和 4 个前端单测；未构建或运行测试。Rust 格式及语法解析检查通过，前端仅静态阅读核对。

剩余边界：原生拖放及 macOS 书签的端到端行为未验证；未指定 notebookId 的调用仍依赖调用时的当前笔记本。Base64 输入仍整体解码到内存。源文件授权仍沿用应用会话共享模型，外部进程操作引起的 TOCTOU 风险未完全消除。

## 后续批次：附件归属及编辑器生命周期

- 富文本编辑器以笔记 ID 配置附件扩展，文件选择、粘贴、拖放和程序化插入均携带该 ID，不再向后端传空 notebookId 并依赖全局选择。
- 后端要求明确的 memoId 或 notebookId。笔记归属从索引解析；未知笔记、未知笔记本或相互矛盾的 ID 均拒绝，不回退到当前笔记本。
- 归属复核与附件提交持有同一跨进程写锁，避免归属检查后再提交的竞争窗口。
- 异步选择或上传完成后，原编辑器已销毁或变为只读时不再插入内容。
- 新增 3 个 Rust 测试及 3 个前端测试，并更新此前上传测试以提供明确归属。未构建、未运行测试；Rust 格式及语法解析检查通过。

兼容性：直接调用附件 IPC 的其他客户端必须提供明确的 notebookId 或 memoId；不属于已注册笔记的富文本编辑器不再默认往当前笔记本导入附件。自定义保存回调仍自行管理存储归属。已经持久化但因编辑器关闭未插入的附件可能成为孤立文件，尚未实现清理机制。

## 后续批次：Base64 资源边界

- Base64 附件通道的解码内容上限为 64 MiB，前端在 FileReader 读取之前按文件大小拦截，后端独立限制编码长度和实际解码字节数。
- 后端不再通过多次 replace、补齐字符串和完整 Vec 解码复制整个内容；使用借用输入的规范化读取器，兼容标准及 URL-safe 字母表、有无 padding，并流式解码到现有原子提交临时文件。
- 解码格式错误或超限都返回错误，不以截断内容提交附件；临时文件由现有失败清理路径释放。
- 原生路径导入和自定义文件保存回调不套用 Base64 上限；自定义内容保存回调同样受前端 Base64 上限约束。
- 新增 6 个解码边界测试、1 个解码失败存储测试和 2 个前端限制测试。Rust 格式及语法解析检查通过；未构建、未运行测试。

限制：Tauri 接收参数前仍需承载完整 Base64 字符串，此改动不是 IPC 层请求大小限制；前端 FileReader 也仍生成完整编码字符串。并发上传配额、分块传输、原生大文件容量策略及孤立附件清理尚未实现。超限沿用现有上传失败日志与失败项不插入策略，尚无专门的大小超限提示界面。
