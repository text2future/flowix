## 推进本主题

本主题流程：案例筛选 → 客户采访 → 事实核验 → 授权审稿 → 入库复用。

1. **案例筛选**：挑选问题明确、客户愿意配合且有结果依据的项目。
2. **客户采访**：围绕原问题、采用过程和变化采访，区分客户原话与整理。
3. **事实核验**：核对时间、数量、效果口径和个人贡献，删除无法证实的表述。
4. **授权审稿**：把拟公开版本发给有权确认的人，记录授权范围与修改意见。
5. **入库复用**：以确认版本入库，记录销售使用场景并安排定期更新。

- 任务入口：`进度视图.csv`。按事项ID查找记录，展示给用户时使用任务名称。
- 决策与依据：`线索/计划表.csv`、`线索/资料/资料清单.csv`。
- 新任务：复制 `公共/客户案例制作单.md`，在 `案例/` 下用可读的任务名称建目录；场次、批次等重复任务加日期。
- 填写案例与真实任务时沿用空白模板的标题和字段，不另造一套简化结构。字段不适用写明原因；资料缺失时说明缺口及影响。过程写已发生的动作，产物保存到任务目录并登记实际路径。
- 结果写入 `数据/案例使用.csv`，沿用同一事项ID。检查字段单位、时间范围和对象粒度；单次任务不填项目累计数。缺失值不得用0代替。
- 本主题完成条件：客户确认事实、数据和公开权限。先逐项核对模板中的审核字段，再更新状态；缺少影响验收的证据时保持待确认。

## 本库中的教学记录

`案例/零售客户门店排班案例/任务记录.md` 与 `案例/零售客户门店排班案例/排班客户案例稿.md` 展示一次任务的记录及产物。其中人物和数据为模拟；未经用户要求，不把模拟数据当作真实事实或继续虚构实际结果。外部发布、支付和联系按用户授权执行。

数据记录先确认一行代表什么对象、哪段时间与什么单位。原始记录、分类合计和项目汇总分别维护；验收表的期望结果必须与实际结果逐项对应，不能只填写“通过”。
