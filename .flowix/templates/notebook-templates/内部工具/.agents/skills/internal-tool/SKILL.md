## 推进本主题

本主题流程：流程盘点 → 需求定义 → 开发试用 → 权限测试 → 团队推广。

1. **流程盘点**：观察团队现有操作，记录重复劳动、交接点和权限问题。
2. **需求定义**：写清角色、输入字段、输出结果和本期不做的功能。
3. **开发试用**：在测试环境实现并让小范围使用者完成实际任务。
4. **权限测试**：分别验证可操作范围、越权拒绝和异常恢复。
5. **团队推广**：准备简短操作说明，分批推广并跟踪使用问题。

- 任务入口：`进度视图.csv`。按事项ID查找记录，展示给用户时使用任务名称。
- 决策与依据：`需求与权限/计划表.csv`、`需求与权限/资料/资料清单.csv`。
- 新任务：复制 `公共/功能交付单.md`，在 `需求与权限/` 下用可读的任务名称建目录；场次、批次等重复任务加日期。
- 填写案例与真实任务时沿用空白模板的标题和字段，不另造一套简化结构。字段不适用写明原因；资料缺失时说明缺口及影响。过程写已发生的动作，产物保存到任务目录并登记实际路径。
- 结果写入 `数据/权限与验收.csv`，沿用同一事项ID。检查字段单位、时间范围和对象粒度；单次任务不填项目累计数。缺失值不得用0代替。
- 本主题完成条件：权限、数据迁移和实际使用者验收。先逐项核对模板中的审核字段，再更新状态；缺少影响验收的证据时保持待确认。

## 本库中的教学记录

`需求与权限/线索自动分配功能/任务记录.md` 与 `需求与权限/线索自动分配功能/线索分配验收.md` 展示一次任务的记录及产物。其中人物和数据为模拟；未经用户要求，不把模拟数据当作真实事实或继续虚构实际结果。外部发布、支付和联系按用户授权执行。

数据记录先确认一行代表什么对象、哪段时间与什么单位。原始记录、分类合计和项目汇总分别维护；验收表的期望结果必须与实际结果逐项对应，不能只填写“通过”。
