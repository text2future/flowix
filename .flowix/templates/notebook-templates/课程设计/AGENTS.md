# AGENTS.md — 课程设计 工作区代理指南

本文件面向在本工作区运行的所有 AI Agent（智能体）。它定义了工作区的目的、结构约定，以及每个技能何时、如何被调用。人类用户请优先阅读 `README.md`。

## 一、工作区定位

这是一个**课程设计笔记本**，用一套固定目录 + 一组专职 Agent 技能，把「课标解读 → 单元整体设计 → 课时设计 → 作业与评价设计 → 课堂实施 → 复盘」的全流程收敛到一个可复制、可追溯的空间里。

- 目标用户：一线教师、教研组长，或需要做系统化备课 / 课程建设的教学工作者。
- 核心资产：课程规则（课标 / 教材 / 学情 / 评价要求）、学期与单元设计、课时设计、作业与评价、课堂复盘与教研问题库。
- 协作方式：每个技能只做一件事，上游产物是下游的输入；**课程规则是所有设计共同遵守的标尺**。

## 二、目录结构与职责映射

| 目录 | 职责 | 主要协作技能 |
| --- | --- | --- |
| `课程规则/` | 课标要点、教材版本、学情、学校要求、评价与作业原则、进度规则（所有设计的标尺） | 全部技能 |
| `学期课程/` | 按学年学期组织：学期计划、各单元设计、课时、单元复盘、学期复盘 | 单元整体设计 / 课时教学设计 / 作业与评价设计 / 课堂复盘 |
| `资源库/` | 课件与素材、作业与评价归档、优秀课例 | 课时教学设计 / 作业与评价设计 |
| `教研与复盘/` | 课堂反思、听评课记录、教学问题库 | 课堂复盘 |

## 三、课程设计流水线（标准顺序）

1. **单元整体设计** — 读 `课程规则/` + `学期课程计划.md`，产出 `学期课程/<学期>/第N单元-<slug>/单元设计.md`，含目标、大概念、课时安排、评价方案。
2. **课时教学设计** — 把单元拆成课时，产出 `.../第N单元-<slug>/课时/第N课时-<slug>.md`。
3. **作业与评价设计** — 为每个课时 / 单元设计作业与评价标准，产出 / 归档到 `资源库/作业与评价/`，并在课时设计中引用。
4. **课堂实施（人类授课）** — 授课后把课件、学生作品等放入 `资源库/课件与素材/`。
5. **课堂复盘** — 授课后基于实录做单元复盘 `.../第N单元-<slug>/单元复盘.md`，反思沉淀到 `教研与复盘/课堂反思/` 与 `教学问题库.md`。

> 不是每个单元都要走完 5 步。纯规划阶段停在「单元整体设计」；已授课的才进入「课堂复盘」。

## 四、文件与命名约定

- 严格遵循 `项目说明/命名规范.md`。核心规则：
  - 学期目录：`YYYY-YYYY学年上/下学期`（如 `2026-2027学年上学期`）。
  - 单元目录：`第N单元-<slug>`（如 `第一单元-数与代数`）。
  - 课时文件：`第N课时-<slug>.md`，置于 `单元/课时/` 下。
  - 学期 / 单元复盘：固定名 `学期复盘.md` / `单元复盘.md`。
- 所有正文用 Markdown；课件等二进制素材放 `资源库/课件与素材/`，正文只放链接与说明。
- 不删除历史设计；过时内容在文档内标记状态，不抹除。

## 五、Agent 协作原则

- **规则优先**：任何设计都必须先过 `课程规则/`，课标与学校要求是硬约束。
- **谁的输入谁负责**：调用下游技能前，先确认上游产物已就绪且路径正确。
- **只动自己职责内的文件**：单元设计不替你写课时；作业设计不直接改单元目标。
- **留下可追溯的痕迹**：在对应文档的「状态 / 修订日志」区记录做了什么、何时做的。
- **不确定就问**：涉及真实授课安排、学生数据等外部动作前，必须获得用户确认。
- **中文输出**：除专有名词外，一律使用简体中文。
