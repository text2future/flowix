# 买卖前检查

## 触发条件
- 用户拟定买入 / 卖出，或标的研究结论为「买」。
- 用户说「检查这笔交易 / 帮我看看这单能不能做」。

## 输入
- 交易计划草稿（或口述的买卖意图）。
- `投资规则/投资规则.md`（筛选、仓位、禁止项）。
- `投资规则/资金与风险边界.md`（单笔上限、现金下限）。
- `投资组合/持仓清单.md`（当前仓位，用于模拟交易后占比）。

## 输出
- 检查报告：逐条「✅ 通过 / ⚠️ 提示 / ❌ 驳回」，标注触线项。
- 通过的：在 `研究与计划/交易计划/待确认/YYYYMMDD-<slug>-<买或卖>.md` 建计划。
- 驳回的：列出阻塞项，交用户决定，不生成计划。

## 检查维度
1. **筛选合规**：标的是否满足《投资规则》准入条件，是否踩一票否决。
2. **仓位越界**：交易后单标的 / 单行业 / 现金下限是否越线（用持仓清单模拟）。
3. **资金边界**：单笔是否超 `资金与风险边界.md` 上限。
4. **禁止清单**：是否杠杆 / 追高 / 情绪单 / 不懂的衍生品。
5. **逻辑自洽**：买卖理由与标的研究结论是否一致。

## 工作流程
1. 抽取交易要素（标的、方向、金额、价格）。
2. 读取规则与当前持仓，逐项核查。
3. 模拟交易后组合占比，算越界风险。
4. 输出报告；通过则生成交易计划并标「待确认」。
5. **不执行真实下单**——只到「待确认」，等用户拍板。

## 质量清单
- [ ] 交易后仓位已模拟（非空想）
- [ ] 触及任何红线即驳回并说明
- [ ] 未获用户确认前不生成「已执行」记录

## 衔接
- 上游：标的研究（结论为「买」）
- 下游：用户执行 → 更新 `投资组合/` 三件套 → 触发组合检查
