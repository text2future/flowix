# 场景设计与诊断

## 触发条件
- 动笔前要把章节拆成场景，或某场景效果不佳需要诊断。
- 上游就绪：`大纲/章节总览.md` 已完成。

## 输入
- `大纲/故事总纲.md`、`章节总览.md`
- `人物/当前人物状态.md`（场景中人物处境）
- `小说设定/故事事实与规则.md`（场景中规则约束）

## 输出
- `大纲/场景总览.md`（章节 → 场景分解）
- 关键场景的场景卡片（`场景卡片` 模板）
- 诊断意见（哪些场景可删 / 需合并 / 缺冲突）

## 工作流
1. 每个场景写清：场景目标、冲突、转折、结果（推进了什么）。
2. 标注视角、地点、时间、出场人物。
3. 诊断：无冲突 / 无推进 / 与主题无关的场景标出处理方式。
4. 更新 `大纲/场景总览.md` 与场景卡片。

## 质量检查清单
- [ ] 每个场景都有目标与冲突（否则考虑删）
- [ ] 每个场景都推进情节或人物
- [ ] 场景间因果衔接清楚
- [ ] 视角 / 地点 / 时间明确
- [ ] 诊断出无效场景并给出处理建议

## 上游 / 下游
- 上游：`大纲与章节规划`
- 下游：`章节续写`（按场景卡动笔）
