# 版本规则

> 长篇创作最怕"改坏了找不回来"。本文规定改写与留痕方式。

## 一、什么时候要留痕

- 修改**重要情节 / 设定 / 结局**前。
- 大规模删章、并章、调序前。
- 发布 / 投稿前的定稿。

## 二、如何留痕（三选一或叠加）

1. **Git**：本工作区可用 git 管理，重要改动前 `commit`，改动清楚可分次提交。
2. **副本**：复制文件加后缀，如 `第001章-雾中来信.20260924.bak.md`，或放 `正文/已删除片段/`。
3. **修订记录**：在 `../修订/章节修订记录/` 记下改了什么、为什么。

## 三、版本标记

- 章节文档可在元数据里标：`status: 初稿 / 二稿 / 定稿`。
- 全书轮次记在 `../修订/修订总览.md`（第 N 轮修订）。

## 四、禁止

- 禁止直接覆盖重要旧稿而不留痕。
- 禁止删除正文；废弃片段入 `../正文/已删除片段/`。

## 五、与技能的关系

- 「结构修订」「文字润色」在动手前必须遵守本规则。
- Agent 不确定改动是否重大时，先问用户。
