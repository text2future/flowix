# AGENTS.md — 工作管理 工作区代理指南

本文件面向在本工作区运行的所有 AI Agent（智能体）。它定义了工作区的目的、结构约定，以及每个技能何时、如何被调用。人类用户请优先阅读 `README.md`。

## 一、工作区定位

这是一个**个人 / 团队工作管理笔记本**，用一套固定目录 + 一组专职 Agent 技能，把「收集 → 规划 → 执行 → 复盘 → 归档」的全流程收敛到一个可复制、可追溯的空间里。

- 目标用户：需要系统化管理工作与项目的职场人、自由职业者、小团队负责人。
- 核心资产：工作规则、项目、任务、周计划与复盘、会议与决策记录、资料与参考。
- 协作方式：每个技能只做一件事，上游产物是下游的输入；**工作规则是所有动作共同遵守的标尺**。

## 二、目录结构与职责映射

| 目录 | 职责 | 主要协作技能 |
| --- | --- | --- |
| `工作规则/` | 目标、优先级、状态、协作沟通规则（所有动作的标尺） | 全部技能 |
| `项目/` | 按状态分桶（进行中 / 等待中 / 已完成 / 已归档）的项目文件夹 | 项目规划 / 项目归档 |
| `任务/` | 收件箱、本周任务、等待他人、例行、已完成 | 工作收集与整理 / 周计划制定 |
| `计划与复盘/` | 本周计划、历史周计划、周复盘、月度复盘 | 周计划制定 / 工作复盘 |
| `会议与沟通/` | 会议记录、决策记录、待跟进事项 | 会议整理与行动项 |
| `资料与参考/` | 客户与合作方、产品业务、研究灵感、常用链接 | 工作收集与整理 |
| `项目说明/` | 工作区地图、命名规范 | — |

## 三、工作管理流水线（标准顺序）

1. **工作收集与整理** — 把脑子 / 聊天 / 邮件里的杂事倒进 `任务/收件箱.md`，分类为项目、任务、参考资料。
2. **项目规划** — 对成形的项目做规划，产出 `项目/进行中/<slug>/项目说明.md`。
3. **周计划制定** — 把项目拆成本周动作，产出 `计划与复盘/本周计划.md` 与 `任务/本周任务.md`。
4. **会议整理与行动项** — 会后产出 `会议与沟通/会议记录/`、`决策记录.md`、`待跟进事项.md`。
5. **工作复盘** — 周末 `周复盘/`、月末 `月度复盘/`，对照目标看达成。
6. **项目归档** — 完成的项目从 `进行中` 移到 `已完成` → 稳定后 `已归档`。

> 不是每件事都要走完 6 步。一件小事进收件箱 → 本周任务 → 已完成即可；只有成形的项目才进「项目规划」。

## 四、文件与命名约定

- 严格遵循 `项目说明/命名规范.md`。核心规则：
  - 项目：`项目/<状态>/<slug>/项目说明.md`（slug 短横线，如 `官网改版`）。
  - 周计划：`计划与复盘/本周计划.md`（当前），归档 `历史周计划/YYYY-Www-周计划.md`。
  - 周复盘：`计划与复盘/周复盘/YYYY-Www-周复盘.md`。
  - 月度复盘：`计划与复盘/月度复盘/YYYY-MM-月度复盘.md`。
  - 会议记录：`会议与沟通/会议记录/YYYYMMDD-<slug>.md`。
- 任务以列表项活在 `任务/*.md` 中；复杂任务可用 `模板/任务.md` 卡片单独成文。
- 所有正文用 Markdown；不删除历史，归档而非抹除。

## 五、Agent 协作原则

- **规则优先**：任何规划 / 优先级判断都必须先过 `工作规则/`。
- **谁的输入谁负责**：调用下游技能前，确认上游产物已就绪且路径正确。
- **只动自己职责内的文件**：项目规划不直接改周计划；会议整理不直接建项目。
- **留下可追溯的痕迹**：在文档的「状态 / 日志」区记录做了什么、何时。
- **不确定就问**：涉及对外沟通、承诺截止日等动作前，必须获得用户确认。
- **中文输出**：除专有名词外，一律简体中文。
