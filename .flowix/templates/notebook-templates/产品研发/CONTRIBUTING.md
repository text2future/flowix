# 贡献指南（CONTRIBUTING）

欢迎参与本产品研发仓库。以下约定适用于人类与 AI 协作者。

## 一、开始之前
1. 完成 `开发者入口/开发环境准备.md` 与 `本地启动与调试.md`。
2. 阅读 `.agents/rules/开发原则.md`、`代码规范.md`、`Git与PR规则.md`。
3. 阅读 `.agents/context/` 了解现状。

## 二、变更流程（新功能 / 修改）
1. 在 `产品输入/活跃Story索引.md` 找到或登记需求。
2. 建变更目录：`变更/进行中/CHG-YYYY-NNN-<slug>/`，用 `.agents/templates/变更/` 下的模板填 `变更说明.md`。
3. 依次完成：`影响分析.md` → `实现计划.md` → 契约更新 → 实现 → `验证计划.md` / `验证记录.md` → `发布计划.md`。
4. 走 PR（见下），发布后写 `收敛记录.md`。

## 三、缺陷流程
- 报缺陷用 `.agents/templates/缺陷/缺陷报告.md`，放 `事件与问题/进行中缺陷/`。
- 修复后用 `修复验证.md` 记录验证，移入 `事件与问题/已修复缺陷/`。

## 四、提交与 PR
- 小步提交，一个提交做一件事；提交信息清晰（见 `Git与PR规则.md`）。
- PR 必须：关联变更 / 缺陷编号、说明影响面、附验证方式、通过 CI。
- 至少一名 CODEOWNER 审阅（见 `CODEOWNERS`）。

## 五、代码质量
- 通过 lint / 类型检查 / 单测；新增逻辑要有测试。
- 不引入未在 `.agents/rules/` 允许范围内的新依赖（新依赖需 ADR）。

## 六、文档同步
- 改了契约 → 更新 `模块与契约/`。
- 做了架构决策 → 写 ADR（`架构决策/ADR/`）。
- 踩了坑 / 有经验 → 写 `.agents/memory/`。

## 七、安全
- 见 `SECURITY.md`；不提交密钥、不绕过鉴权、不留后门。
