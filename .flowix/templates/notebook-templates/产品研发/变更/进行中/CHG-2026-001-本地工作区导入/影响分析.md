# CHG-2026-001 · 影响分析

> 目标：**在动手前把"会碰到什么"想清楚**，而不是边写边发现。分析结论要落到任务。

## 一、影响面

| 层面 | 是否影响 | 说明 |
| --- | --- | --- |
| 前端 | 是 | 新增导入流程与进度 UI |
| 后端 / 主进程 | 是 | 目录扫描、索引写入 |
| API / 契约 | 是 | 新增导入端点（见 `模块与契约/API/API目录.md`） |
| 数据 | 是 | 新增工作区记录 |
| 桌面端能力 | 是 | 文件系统只读访问 |
| 文档 | 是 | `开发者入口/` 与 `.agents/context/` 需更新 |

## 二、风险

| # | 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| R1 | 大目录导致内存暴涨（已有 `F-06`） | 高 | 高 | 分批 + 上限 + 可中断 |
| R2 | 中文检索命中率不足 | 中 | 中 | 专项评测，不足则记录为已知限制 |
| R3 | 平台路径差异 | 中 | 中 | 统一走平台 API |

> 只列**需要应对**的风险；每条**必须**有对应任务或明确"接受"。

## 三、不做的影响分析

| 不做 | 后果 |
| --- | --- |
| 增量索引 | 变更后索引延迟到下次扫描，可接受 |

## 四、结论

可做。前置条件：先解决 R1 的分批策略（对应任务 T2）。
