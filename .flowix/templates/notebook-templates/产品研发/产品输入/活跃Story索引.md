# 活跃 Story 索引

> **研发的入口表。** 只放**未交付**的 Story；交付后移入 `历史归档/`。  
> 每个 Story 应能追溯到目标（`当前产品目标.md`）与验收（`用户流程与验收.md`）。

## 一、Story 清单


| ID     | Story           | 目标      | 优先级    | 状态  | 变更           |
| ------ | --------------- | ------- | ------ | --- | ------------ |
| ST-101 | &lt;一句话用户价值&gt; | O1 / O3 | P0     | 开发中 | CHG-2026-001 |
| ST-102 |||| 待开始 ||


> **状态只用**：待开始 / 开发中 / 已交付 / 已取消。字段不要杜撰。

## 二、填写范例

### ST-101 · 导入本地目录为工作区


| 项    | 内容                                    |
| ---- | ------------------------------------- |
| 目标   | O1（导入可用）、O3（大目录不损伤体验）                 |
| 用户价值 | 用户不必重建已有目录，直接纳管                       |
| 验收   | 见 `用户流程与验收.md#UF-03`                  |
| 设计   | `设计稿与交互说明.md#DS-01`                   |
| 变更   | `变更/进行中/CHG-2026-001-本地工作区导入/变更说明.md` |


**不做（本 Story 范围外）**：增量实时索引、云端同步（`GD-004`）。

## 三、维护规则

- Story 启动 → 建 `变更/CHG-xxx/` 并在本表关联。
- Story 交付 → 移入 `历史归档/已完成变更/`，从本表删除。
- 每周与产品对一次本表，避免"研发在做已经取消的事"。
