# 产品研发仓库 · 说明

本仓库是一套**产品研发工程模板**：除了代码本身，它把变更、契约、测试、发布、事件、决策、经验都沉淀成目录化资产，让"为什么这么改、改了影响什么、怎么回滚"永远有据可查。

## 一、这套结构解决什么

- **变更可追溯**：每个需求 / 修改都是一个 `变更/CHG-xxxx/`，从影响到发布到收敛全程留痕。
- **契约不漂**：前后端 / API / 数据 / 桌面端的契约统一放 `模块与契约/`。
- **规则可执行**：`.agents/rules/` 是硬约束，人和 AI 都按它来。
- **上下文即真相**：`.agents/context/` 描述真实代码结构，AI 不再"猜"。
- **经验可积累**：`.agents/memory/` 记录决策、陷阱、排查路径，越用越顺。
- **运行更稳**：发布清单、回滚 / 运行手册、SLO、事件复盘齐备。

## 二、给新成员 / 新 AI 的第一课

1. 读 `开发者入口/新成员上手.md` → 本地跑起来。
2. 读 `.agents/context/代码地图.md` 与 `.agents/rules/架构边界.md`。
3. 读 `.agents/rules/开发原则.md` 与 `Git与PR规则.md`。
4. 接活时：从 `产品输入/活跃Story索引.md` → 建 `变更/` → 按 `AGENTS.md` 的流水线走。

## 三、目录地图


| 目录         | 放什么                                                        |
| ---------- | ---------------------------------------------------------- |
| `.agents/` | skills（技能）、rules（规则）、context（上下文）、templates（模板）、memory（记忆） |
| `开发者入口/`   | 上手、环境、命令、PR、发布等入门文档                                        |
| `变更/`      | 变更目录（进行中 / 待开始 / 已完成 / 已归档）                                |
| `模块与契约/`   | 前端 / 后端 / API / 数据 / 桌面端 的模块与契约                            |
| `测试与验证/`   | 测试策略与分层、冒烟 / 回归 / E2E、性能 / 安全、报告                           |
| `发布与运行/`   | 环境、配置、灰度、发布清单、回滚 / 运行手册、监控、SLO                             |
| `事件与问题/`   | 缺陷队列与缺陷、已知限制、线上事件、事故复盘、防回归                                 |
| `架构决策/`    | ADR、技术债务、架构演进、依赖升级                                         |
| `产品输入/`    | 产品目标、Story、用户流程、设计稿、反馈、非目标                                 |
| `历史归档/`    | 已完成变更、已替代规范、历史发布 / 事件                                      |


## 四、常用入口

- 协作规范（AI）：`AGENTS.md`
- 贡献指南：`CONTRIBUTING.md`
- 安全策略：`SECURITY.md`
- 所有者：`CODEOWNERS`
- 技能与模板：`.agents/skills/`、`.agents/templates/`

## 五、重要提醒

- **不要绕过规则**：`.agents/rules/` 是硬约束。
- **不要臆测代码**：以 `.agents/context/` 与真实代码为准。
- **不可逆操作先确认**：生产发布、数据删除、迁移回滚等必须先获确认。
