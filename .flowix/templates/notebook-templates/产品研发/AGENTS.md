# AGENTS.md — 产品研发 工作区代理指南

本文件面向在本工作区运行的所有 AI Agent（智能体）。它定义了本仓库的定位、结构约定，以及每个技能何时、如何被调用。人类用户请优先阅读 `README.md` 与 `开发者入口/`。

## 一、工作区定位

这是一个**产品研发仓库**：既是代码库的工程协作空间，也是围绕代码的**决策、上下文、记忆**中枢。目标是把「理解现状 → 计划变更 → 设计契约 → 实现 → 测试 → 审查 → 发布 → 运行与事件 → 收敛」的全流程收敛成可追溯的工程资产。

- 目标用户：研发团队（含单人项目）；AI 作为结对工程师参与。
- 核心资产：变更记录、模块与契约、测试与验证、发布与运行、事件与复盘、架构决策、产品输入。
- 协作方式：每个技能只做一件事，上游产物是下游输入；**`.agents/rules/` 是硬约束，`.agents/context/` 是背景事实，`.agents/memory/` 是长期经验。**

## 二、核心机制（三个特殊目录）

| 目录 | 作用 | 谁维护 |
| --- | --- | --- |
| `.agents/rules/` | **规则（硬约束）**：开发原则、代码规范、架构边界、API/数据/测试/安全/可观测性/Git/发布规则 | 团队，人定 |
| `.agents/context/` | **上下文（事实）**：代码地图、模块边界、领域模型、技术栈、契约、存储、依赖、运行架构、常见故障 | 随代码进展更新 |
| `.agents/memory/` | **记忆（经验）**：工程决策、经验与陷阱、常见排查路径、未解决技术问题 | 技能写回 |

> 任何变更开始前：先读 `.agents/context/`（现状）→ 合规 `.agents/rules/`（约束）→ 查 `.agents/memory/`（踩过的坑）。

## 四、研发流水线（标准顺序）

**变更主线（新功能 / 修改）**
1. **代码库理解与影响分析** → `变更/<id>/影响分析.md`
2. **变更实现计划** → `变更/<id>/实现计划.md`、`任务与进度.md`
3. **API与数据契约设计** → 更新 `模块与契约/`、`变更/<id>/实现计划.md`
4. **实现**（人类 + Agent 写代码）→ 更新 `任务与进度.md`
5. **测试设计与验证** → `验证计划.md`、`验证记录.md`、`测试与验证/`
6. **代码审查与风险检查** → PR 评审 + 风险清单
7. **发布准备与回滚** → `发布计划.md`、`发布与运行/`、`发布与运行/发布记录/`
8. **代码与规格收敛** → `收敛记录.md`，回写 `.agents/context/`、`.agents/memory/`、`模块与契约/`

**缺陷线（并行）**
- **缺陷定位与修复** → `事件与问题/` + `变更/<id>/`（如涉及）

**运行线（并行）**
- **性能与可靠性分析**、**线上事件诊断与复盘** → `事件与问题/`、`发布与运行/`

## 五、文件与命名约定

- 变更：`变更/<状态>/CHG-YYYY-NNN-<slug>/`（内含 `变更说明.md` 等固定文件）。
- ADR：`架构决策/ADR/<状态>/ADR-NNN-<slug>.md`。
- 缺陷：`事件与问题/<状态>/BUG-NNN-<slug>.md`。
- 事件：`事件与问题/线上事件/INC-YYYYMMDD-<slug>.md`。
- 发布记录：`发布与运行/发布记录/YYYY-MM-DD-<版本>-发布记录.md`。
- 所有正文用 Markdown；详细命名见 `开发者入口/` 与各目录 README。

## 六、Agent 协作原则

- **规则优先**：写码 / 设计前先读 `.agents/rules/`，不得违背。冲突时停下来问用户。
- **上下文优先**：不臆测代码结构，以 `.agents/context/` 与真实代码为准。
- **变更驱动**：任何实现都挂在某个 `变更/<id>/` 下，先有计划再动手。
- **留下痕迹**：决策写 ADR，经验写 `.agents/memory/`，变更过程写 `变更/<id>/`。
- **小步可回滚**：优先小步提交、可灰度、可回滚。
- **不确定就问**：涉及数据删除 / 生产发布 / 不可逆操作，必须先获用户确认。
- **中文输出**：除代码、专有名词外，一律简体中文。
