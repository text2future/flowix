# 监控与告警

> **前提**：告警必须**可行动**。没有对应 Runbook 的告警**不得上线**——否则只会训练团队忽略告警。

## 一、监控维度

| 维度 | 看什么 | 位置 |
| --- | --- | --- |
| 可用性 | 服务 / 进程是否存活 | 健康检查 |
| 错误率 | 请求失败比例、崩溃率 | 错误统计 |
| 延迟 | P50 / P95 / P99 | 延迟面板 |
| 资源 | CPU / 内存 / 磁盘 / 句柄 | 资源面板 |
| 业务 | 核心动作成功率（如导入成功率） | 业务指标 |
| 客户端 | 崩溃、卡顿、白屏 | 客户端上报 |

## 二、告警清单

| # | 告警 | 条件 | 级别 | Runbook | 负责人 |
| --- | --- | --- | --- | --- | --- |
| AL-01 | <服务不可用> | <健康检查连续失败 N 次> | P0 | `发布与运行/运行手册/<...>.md` | <姓名> |

## 三、告警要求

| 要求 | 说明 |
| --- | --- |
| 可行动 | **必须**有 Runbook 链接 |
| 有分级 | 级别决定响应方式与时限 |
| 有抑制 / 聚合 | 防告警风暴 |
| 有负责人 | 无主告警等于无告警 |
| 阈值有依据 | 基于实测基线，不拍脑袋 |

## 四、日志规范

| 项 | 要求 |
| --- | --- |
| 结构 | 结构化（可检索字段） |
| 追踪 | 带请求 / 追踪 ID，可串起一次调用 |
| 级别 | 按级别使用；**禁止**全用 error |
| 敏感信息 | **禁止**记录凭据 / 个人敏感数据 |
| 保留 | 见 `模块与契约/数据/数据生命周期.md` |

## 五、Runbook 缺口（待创建）

以下告警**上线前必须先补齐对应 Runbook**（本模板未附实例）：

| 告警 | 需补 Runbook |
| --- | --- |
| AL-01 | 服务不可用处理 |
| — | 索引异常 / 卡住处理 |
| — | 内存或资源异常处理 |
| — | 回滚操作手册 |
| — | 密钥 / 凭据泄露处理 |

> 模板格式见 `.agents/templates/Runbook.md`。

## 六、维护规则

- 新增告警 → 登记本表 + 补 Runbook + 指定负责人，**三者缺一不可**。
- 阈值变化 → 更新本表。
- 每次线上事件后 → 检查"为什么没告警"或"为什么告警了却没人行动"。
