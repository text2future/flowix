# Feature Flag 与灰度

> **让"发布"和"上线"分离。** 代码可先合入但默认关闭，风险可控地逐步放量。

## 一、Flag 类型

| 类型 | 用途 | 生命周期 |
| --- | --- | --- |
| 发布开关 | 新功能灰度放量 | **短期**，全量后删除 |
| 实验开关 | 对比不同方案 | 实验结束即清理 |
| 运维开关 | 紧急降级 / 熔断 | 长期保留 |
| 权限开关 | 按账号 / 组织开放 | 视情况 |

> **反模式**：把 Flag 当配置长期留着 → 分支越积越多。**发布型 Flag 全量后必须清理**，并登记到期时间。

## 二、Flag 清单

| 名称 | 类型 | 默认 | 放量策略 | 到期 | 负责人 |
| --- | --- | --- | --- | --- | --- |
| `<flag>` | 发布 | 关 | 内部 → 5% → 50% → 100% | <日期> | <姓名> |

## 三、灰度策略

```
内部 → 小比例 → 观察窗口 → 放大 → 全量
         └─ 指标异常 → 立即关闭（不是"再看看"）
```

| 项 | 要求 |
| --- | --- |
| 每步观察窗口 | 至少覆盖一个业务周期，不看"半小时没事" |
| 放量依据 | 指标达标，而非"感觉没问题" |
| 回滚 | 关闭开关即可，**不必**发版 |
| 隔离 | 同一用户在各端看到一致行为（避免体验割裂） |

## 四、与回滚的关系

| 情况 | 首选动作 |
| --- | --- |
| 逻辑问题、开关还在 | **关开关**（最快） |
| 数据 / 结构问题 | 走回滚（见 `.agents/rules/发布与回滚规则.md`） |
| 开关已全量删除 | 只能回滚版本 |

## 五、维护规则

- 新增 Flag → 登记本表，**必须**填到期时间。
- Flag 全量 → 安排清理任务（删除代码分支 + 从本表移除）。
- 每次发布前检查：是否有**过期未清理**的 Flag。
