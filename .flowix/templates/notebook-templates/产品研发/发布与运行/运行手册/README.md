# 运行手册

日常运维、开关、重启、扩容等操作手册（Runbook）。

模板见 `../../.agents/templates/Runbook.md`。每份 Runbook 必须包含：现象、影响判断、排查步骤、止血手段、恢复验证、升级路径、演练记录。

## 一、必需 Runbook（**待创建**）

> 本目录当前为空。下表每份都对应 `../监控与告警.md` 的告警或常见故障，**该告警上线前必须补齐对应手册**（有告警无手册 = 值守时无从下手）。

| Runbook | 对应告警 / 故障 | 状态 |
| --- | --- | --- |
| `<服务>-不可用.md` | 服务 / 进程不可用 | ⏳ 待创建 |
| `<服务>-错误率升高.md` | 错误率超阈 | ⏳ 待创建 |
| `<服务>-延迟升高.md` | 延迟超阈 | ⏳ 待创建 |
| `资源异常.md` | CPU / 内存 / 磁盘 / 句柄超阈 | ⏳ 待创建 |
| `任务积压.md` | 队列 / 后台任务积压 | ⏳ 待创建 |
| `回滚操作.md` | 需要紧急回滚 | ⏳ 待创建 |
| `密钥轮换与泄露.md` | 凭据疑似泄露 | ⏳ 待创建 |
| `数据异常处理.md` | 数据损坏 / 不一致 | ⏳ 待创建 |

> 实际要写哪几份，以你自己的 `../监控与告警.md` 告警清单为准；**每条告警都必须有对应手册**。

## 二、命名规范

`<域>-<场景>.md`，全小写 + 连字符。例：`db-连接耗尽.md`、`任务积压.md`。

## 三、维护要求

- 每份 Runbook 必须**实际演练过**（见模板第八节），未演练的视为草稿。
- 系统变化后必须同步更新；引用错误的 Runbook 比没有更危险。
- 新增告警 → 必须同时新增或指定对应 Runbook（见 `../监控与告警.md` 第二节）。
- 每次线上事件后检查：Runbook 是否缺少步骤 / 有错误。
