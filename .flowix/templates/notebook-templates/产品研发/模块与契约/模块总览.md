# 模块总览

> 本目录存放**模块说明与契约**。契约是"已经承诺出去的东西"，改动需谨慎（见 `.agents/rules/API与兼容性规则.md`）。
> 与 `.agents/context/` 的分工：context 描述**系统事实**（代码结构、运行架构）；本目录描述**对外承诺的接口与数据结构**。

## 一、目录结构

| 目录 | 内容 | 权威文件 |
| --- | --- | --- |
| `前端/` | 页面路由、状态管理、UI 组件、错误处理 | `页面与路由.md` |
| `后端/` | 服务边界、任务与事件、错误码 | `服务边界.md` |
| `API/` | HTTP 接口目录、认证授权、版本兼容、Webhook | `API目录.md` |
| `数据/` | 数据模型、迁移、生命周期、修复规范 | `数据模型.md` |
| `桌面端与本地能力/` | 文件系统权限、本地索引、IPC、跨平台差异 | `文件系统权限.md` |

## 二、契约全景（谁和谁约定）

> 按你的真实架构替换下面这张图。要点：**把每个"跨边界"的连接都画出来**——它们就是需要契约的地方。

```
┌──────────┐   <边界1>   ┌──────────┐
│  <一侧>   │ ◄─────────► │  <另一侧> │
└────┬─────┘             └─────┬────┘
     │                         │
     │ <边界2>                 ▼
     │                   ┌──────────┐
     └──────────────────►│  <存储>   │
                         └──────────┘
```

| 边界 | 契约类型 | 权威文件 |
| --- | --- | --- |
| <前端 ↔ 主进程 / 客户端> | <IPC / 本地调用> | `模块与契约/桌面端与本地能力/IPC与进程边界.md` |
| <客户端 ↔ 服务端> | HTTP API | `模块与契约/API/API目录.md` |
| <服务 ↔ 服务> | 内部事件 | `模块与契约/后端/任务与事件.md` |
| <系统 ↔ 外部> | Webhook | `模块与契约/API/Webhook与外部集成.md` |
| <系统 ↔ 存储> | 数据模型 | `模块与契约/数据/数据模型.md` |

## 三、契约变更流程

1. **先改契约文档**（本目录），再改代码。
2. 判定兼容性（见 `模块与契约/API/版本与兼容性.md`）：
   - 兼容 → 直接合入，同步 `.agents/context/API与事件契约.md`。
   - 破坏 → 版本化或过渡期，且需 **ADR**。
3. 更新 `.agents/context/API与事件契约.md` 的索引表。
4. 前后端 / 跨端契约变更需**双方 owner** 评审（见 `CODEOWNERS`）。

## 四、契约一致性检查清单

- [ ] 端点 / 事件在本文档目录中有记录
- [ ] 请求 / 响应示例完整（不是"略"）
- [ ] 错误码引用 `模块与契约/后端/错误码与异常约定.md`
- [ ] 数据字段与 `模块与契约/数据/数据模型.md` 一致
- [ ] 兼容性已判定
- [ ] `.agents/context/API与事件契约.md` 已同步

## 五、维护说明

- 新增契约文件 → 更新第一节表格。
- 契约与代码不一致 = **视为缺陷**，按 `缺陷定位与修复` 处理。
- 被替代的契约 → 移入 `历史归档/已替代规范/`，不在原处删除。
