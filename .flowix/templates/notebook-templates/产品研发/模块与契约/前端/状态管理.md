# 状态管理

> 规定状态**存在哪一层**。**状态放错层是前端最主要的复杂度来源。**

## 一、状态分层

| 层 | 存什么 | 生命周期 | 位置 |
| --- | --- | --- | --- |
| 组件本地 | 只在单组件用的 UI 状态 | 组件存活期 | 组件内 |
| 页面 / 会话 | 跨组件共享的页面态 | 页面存活期 | <store> |
| 全局 | 跨页面共享（用户、配置） | 应用存活期 | <store> |
| 服务端态 | 来自接口的数据 | 由缓存策略决定 | <数据层> |

> **判定顺序**：能放本地就不上提；能放页面就不全局；服务端数据**不要**手工塞进全局 store。

## 二、约定

| 项 | 规则 |
| --- | --- |
| 唯一来源 | 同一份数据只有一个权威来源，**禁止**双写 |
| 派生值 | 用计算得到，**不**单独存 |
| 副作用 | 集中在 <action / effect 层>，组件不直接发请求 |
| 持久化 | <哪些状态持久化、存哪里、如何迁移> |

## 三、填写范例

| 状态 | 层 | 理由 |
| --- | --- | --- |
| 当前工作区 | 全局 | 多页面共享 |
| 导入进度 | 页面 | 仅导入页使用，离开即丢弃 |

## 四、维护规则

- 新增全局状态 → 必须写明"为什么不能放页面层"。
- 状态结构变化涉及持久化 → 必须提供**版本迁移**，否则老用户数据会坏。
