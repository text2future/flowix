# 跨平台差异

> 记录**平台间行为不一致**的地方与统一处理方式。**未记录的差异就是未来的缺陷。**

## 一、差异清单

| 能力 | Windows | macOS | Linux | 统一策略 |
| --- | --- | --- | --- | --- |
| 路径分隔符 | `\` | `/` | `/` | 统一用平台 API 拼路径，**禁止**手写分隔符 |
| 大小写敏感 | 不敏感 | 默认不敏感 | 敏感 | 索引与去重**不得**依赖大小写 |
| 换行符 | CRLF | LF | LF | 处理文本时两者都容忍 |
| 文件锁 | 强 | 中 | 弱 | **不得**依赖文件锁做并发控制 |
| 符号链接 | 支持 | 支持 | 支持 | 解析真实路径 |
| 权限模型 | 弱 | 强（沙箱） | 中 | 以**最严**平台为准设计 |

## 二、填写范例

| 能力 | Windows | macOS | Linux | 统一策略 |
| --- | --- | --- | --- | --- |
| 长路径 | 有长度限制 | 无 | 无 | 超限时给出明确提示 |

## 三、处理原则

1. **以最严平台为准**设计，而不是"能跑就行"。
2. 差异**必须**记录并覆盖测试（见 `测试与验证/端到端测试.md`）。
3. 平台分支代码**必须**集中，**禁止**散落各处 `if (platform)`。
4. 无法统一的差异 → 在 UI 或文档中**显式告知用户**。

## 四、维护规则

- 新发现的差异 → 追加本表 + 补测试。
- 差异引发的缺陷 → 定级时考虑"影响面是单平台还是全平台"。
