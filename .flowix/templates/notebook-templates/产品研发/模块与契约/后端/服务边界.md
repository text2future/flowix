# 服务边界

> 规定后端的**职责划分与依赖方向**。跨边界调用**必须**走明确定义的接口。

## 一、服务 / 模块清单

| 模块 | 职责 | 依赖 | 所属数据 |
| --- | --- | --- | --- |
| <模块 A> | <一句话职责> | <可依赖谁> | <拥有哪些表> |
| <模块 B> | | | |

## 二、边界规则

| 规则 | 说明 |
| --- | --- |
| 单一职责 | 一个模块一件事，边界描述要能用一句话说清 |
| 依赖方向 | **禁止**循环依赖；层级方向固定（见 `.agents/rules/架构边界.md`） |
| 数据所有权 | **只有拥有者**能直写该表，其他模块通过接口 |
| 跨模块调用 | 走**接口 / 事件**，**禁止**直接读对方内部实现 |

## 三、填写范例

| 模块 | 职责 | 依赖 | 所属数据 |
| --- | --- | --- | --- |
| `<索引模块>` | 维护本地索引与检索 | `<存储>` | `index_*` 表 |

## 四、维护规则

- 新增模块 → 登记本表 + 更新 `.agents/context/模块边界.md`。
- 边界变更（拆分 / 合并 / 改依赖方向）→ **必须**写 ADR。
