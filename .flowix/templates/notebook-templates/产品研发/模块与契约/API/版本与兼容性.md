# 版本与兼容性

> **兼容性是承诺。** 判定不清楚就不改——先讨论。

## 一、兼容性判定

| 改动 | 判定 | 处理 |
| --- | --- | --- |
| 新增可选字段 | 兼容 | 直接合入 |
| 新增必填请求字段 | **破坏** | 给默认值或版本化 |
| 删除 / 改名响应字段 | **破坏** | 先双写过渡，再下线 |
| 收紧校验 | **破坏** | 灰度并公告 |
| 新增枚举值 | 兼容（**前提**：消费方能容忍未知值） | 确认消费方后再发 |
| 改错误码语义 | **破坏** | 发新码 |

## 二、版本策略

| 项 | 约定 |
| --- | --- |
| 版本载体 | <路径 / 请求头> |
| 并行 | 旧版本至少保留 <N> 个发布周期 |
| 弃用流程 | 标注废弃 → 通知消费方 → 观察调用量 → 下线 |
| 观测 | 按版本统计调用量，确认无人使用才下线 |

## 三、填写范例

| 改动 | 判定 | 处理 |
| --- | --- | --- |
| 响应新增 `itemCount` | 兼容 | 直接合入 |

## 四、维护规则

- 破坏性变更 → **必须**写 ADR + 通知全部消费方（含外部集成）。
- 下线任何端点 → 先在 `模块与契约/API/API目录.md` 标废弃并给出替代者。
