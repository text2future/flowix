# API 目录

> **所有对外 HTTP 端点的唯一登记处。** 未登记的端点视为未完成。

## 一、通用约定

| 项 | 约定 |
| --- | --- |
| 前缀 | `/api/<版本>` |
| 命名 | 资源用**复数名词**，动作用 HTTP 方法表达 |
| 认证 | 见 `模块与契约/API/认证与授权.md` |
| 错误 | 统一返回结构 + 错误码（见 `模块与契约/后端/错误码与异常约定.md`） |
| 分页 | 统一参数与返回结构（游标或页码，全站一致） |
| 幂等 | 写操作支持幂等键（需要时） |

**统一返回结构**

```json
{ "data": {}, "error": null, "meta": {} }
```

## 二、端点清单

| 方法 | 路径 | 用途 | 认证 | 幂等 | 备注 |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/v1/<resources>` | 列表 | 是 | — | 分页 |
| POST | `/api/v1/<resources>` | 创建 | 是 | 幂等键 | |

> 新增端点的完整文件建议按域拆分（如 `API目录-导入.md`），本文件保留索引与通用约定。

## 三、填写范例

| 方法 | 路径 | 用途 | 认证 | 幂等 | 备注 |
| --- | --- | --- | --- | --- | --- |
| POST | `/api/v1/workspaces/import` | 导入本地目录为工作区 | 是 | 需幂等键 | 长任务，返回任务 ID |

## 四、维护规则

- 新增端点 → 登记本表；**破坏性变更**先改 `模块与契约/API/版本与兼容性.md` 再动手。
- 端点下线 → 标注废弃 + 给出替代者，进 `历史归档/已替代规范/`。
- 契约与代码不一致 = **视为缺陷**。
