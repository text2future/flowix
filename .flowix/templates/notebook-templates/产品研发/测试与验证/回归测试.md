# 回归测试

> **定义**：把"曾经出过的问题"固化为用例，防止复发。**关键用例发布前必须全过。**

## 一、用例登记表

| # | 用例 | 来源 | 层 | 关键 | 状态 |
| --- | --- | --- | --- | --- | --- |
| RG-01 | <用例描述> | <BUG-… / INC-… / PT-…> | <单元/集成/E2E> | ✅ | |
| RG-02 | <用例描述> | <来源> | | 否 | |

> "关键 = ✅" 的用例**发布前必须全过**。关键性判断依据：影响数据 / 安全 / 主流程。

## 二、执行

| 项 | 要求 |
| --- | --- |
| 命令 | `pnpm test:regression` |
| 环境 | staging |
| 频率 | 每次发布；大改动后额外跑 |
| 通过标准 | **关键用例全过**；非关键失败需评估 |

## 三、新增时机（必须）

| 情况 | 说明 |
| --- | --- |
| 修复了一个缺陷 | 该缺陷的最小复现用例（**修复前应为红**） |
| 发生了一次线上事件 | 事件复盘的防回归项（`.agents/templates/事件复盘.md`） |
| 发现了一个陷阱 | `.agents/memory/经验与陷阱.md` 条目中可自动化的部分 |
| 新增了兼容性风险 | 如"未知枚举值不崩" |

## 四、用例规范

- **必须在修复前失败**（否则不能防回归）。
- 必须最小化（只覆盖该问题）。
- 必须稳定（不许 flaky）。
- 用例名写明来源，便于追溯。

## 五、与缺陷 / 事件的对应

```
缺陷修复 → 缺陷报告"防回归"节 → 用例加入本表（RG-NN）
线上事件 → 事件复盘"行动项"   → 用例加入本表（RG-NN）
陷阱清单 → memory/经验与陷阱   → 可自动化则加入本表
```

## 六、维护

- 用例对应代码已删除 → 移除用例（git 历史留痕）。
- 用例长期不稳定 → 修复或降级为非关键（记录原因）。
- 每次发布后回顾：是否有新的、应固化的经验。
