# 测试分层

> 定义"什么放哪一层"，避免把所有测试都写成 E2E。

## 一、分层定义

| 层 | 范围 | 依赖 | 速度 | 数量 | 位置 |
| --- | --- | --- | --- | --- | --- |
| 单元 | 单个函数 / 类 / 组件 | 全部 mock | 毫秒级 | **最多** | `tests/unit/` |
| 集成 | 模块间 + 真实 DB / 依赖 | 容器 / 临时库 | 秒级 | 中 | `tests/integration/` |
| 端到端 | 完整用户路径 | 完整应用 | 十秒~分钟级 | **最少** | `tests/e2e/` |
| 手工 / 探索 | 体验 / 跨平台 / 视觉 | 真实环境 | 人工 | 视情况 | 记入验证记录 |

**配比原则**：单元 >> 集成 >> E2E。**禁止**把逻辑验证都推到 E2E（慢、脆、难定位）。

## 二、什么测哪层

| 被测内容 | 应放层 | 理由 |
| --- | --- | --- |
| 纯函数 / 算法 | 单元 | 无依赖，快 |
| 边界 / 异常分支 | 单元 | 容易构造 |
| 组件渲染 / 交互 | 单元 | 快 |
| 仓储 / DAO | 集成 | 需真实 DB |
| API 端点 | 集成 | 需路由 + DB |
| 事务 / 并发 | 集成 | 需真实 DB |
| 迁移 up/down | 集成 | 需真实 DB |
| 关键用户路径 | E2E | 验证真实闭环 |
| 跨平台行为 | E2E + 手工 | 需真实平台 |
| 性能 | 专项基准 | 见 `性能基准/` |

## 三、单元测试规范

**必须**：独立（不依赖顺序 / 共享状态）、可重复（时间 / 随机 / 网络可控）、快速（单文件 < 1s）。

**禁止**：
- `sleep` 等待（用 fake timer / 事件驱动）
- 真实网络 / 生产数据
- 测私有实现细节（应测行为）

## 四、集成测试规范

- 用临时数据库（每次测试独立库 / schema）。
- 外部依赖用容器或 mock 服务（**禁止**连真实第三方）。
- 测试数据用**合成数据**。
- 每个测试自行准备与清理（`beforeEach` / `afterEach`）。
- 必须覆盖：事务回滚、并发、约束冲突。

## 五、mock 约定

| 对象 | 方式 |
| --- | --- |
| 时间 | 注入时钟 / fake timer |
| 随机 | 注入种子 |
| 网络 | mock server / 拦截层 |
| 文件系统 | 临时目录（尽量真实） |

> mock 必须**保持真实契约的形状**（类型一致），**禁止** mock 出真实里不可能出现的响应。

## 六、测试文件组织

```
tests/
├── unit/            # 与源码目录对应
├── integration/
├── e2e/
└── fixtures/        # 合成测试数据
```

## 七、覆盖率

- **不作为目标**：不追求数字达标。
- **作为信号**：核心逻辑（领域层 / 鉴权 / 关键算法）**必须**有单元测试。
- **不测**：生成的代码、纯类型定义、第三方封装的薄层。
