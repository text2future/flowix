# 冒烟测试

> **定义**：发布前必须全过的"基本盘"检查。**不过就不可发布。**

## 一、目的

快速确认"应用能起来 + 主流程能走通"。**不追求全面，追求必过。**

## 二、冒烟用例清单

| # | 用例 | 预期 | 状态 |
| --- | --- | --- | --- |
| SM-01 | 应用启动 | 正常打开，无白屏 | |
| SM-02 | 服务健康检查 | `/healthz` 返回 200 | |
| SM-03 | 登录流程 | 能登录并进入首页 | |
| SM-04 | <核心主流程> | <...> | |
| SM-05 | 未登录访问受保护页 | 跳转登录，不白屏 | |

> **新增核心功能时必须评估是否加入**，但保持这个集合"小"（5–10 分钟能跑完）。

## 三、执行

| 项 | 要求 |
| --- | --- |
| 命令 | `pnpm test:smoke` |
| 环境 | staging（与生产配置一致） |
| 频率 | 每次发布前；CI 定时 |
| 通过标准 | **全部通过** |
| 失败处理 | **立即停止发布**，定位修复 |

## 四、手动冒烟（无法自动化的部分）

| # | 检查 | 平台 |
| --- | --- | --- |
| MS-01 | 窗口 / 页面可缩放，布局不破 | 全平台 |
| MS-02 | 系统级交互正常（文件选择器 / 通知等） | 全平台 |
| MS-03 | 中文内容正确显示 | 全平台 |
| MS-04 | 明暗主题切换正常 | 全平台 |

## 五、冒烟 vs 回归

| 项 | 冒烟 | 回归 |
| --- | --- | --- |
| 范围 | 最小核心集 | 历史缺陷 + 关键路径 |
| 长度 | 5–10 分钟 | 可更长 |
| 目的 | "能不能用" | "老问题有没有复发" |
| 频率 | 每次发布 | 每次发布 + 大改动后 |

## 六、维护

- 新增核心功能 → 评估是否加入冒烟集（保持"小"）。
- 用例**必须**稳定；flaky 的**必须**修或移出。
- 冒烟集变更 → 同步更新 `开发者入口/测试与检查命令.md`。
