# 测试策略

> 本文件回答：**我们靠什么来保证质量。** 执行规则见 `.agents/rules/测试规则.md`；分层定义见 `测试分层.md`。

## 一、总原则

1. **测试是发布门槛**，不是"有时间再做"。
2. **缺陷修复必须先有失败测试**（防回归）。
3. **测行为，不测实现**（重构不应让测试大面积红）。
4. **真实优于推断**：未执行就写"未执行"，**禁止**编造结果。
5. **底部多而快，顶部少而真**（见 `测试分层.md`）。

## 二、质量防线（多层拦截）

```
第 1 层  类型系统 + Lint          ← 提交前，秒级
第 2 层  单元测试                 ← 提交前，秒级
第 3 层  集成测试（DB / 契约）      ← PR 时，分钟级
第 4 层  代码评审（人工 / AI）     ← PR 时
第 5 层  端到端测试               ← 合并后
第 6 层  冒烟测试                 ← 发布前，必须全过
第 7 层  回归测试                 ← 发布前，关键用例必须全过
第 8 层  灰度 + 监控 + 观察窗口    ← 发布时
第 9 层  回滚能力                 ← 兜底
```

> 目标不是"某一层很强"，而是**每层都拦住一部分问题**。

## 三、各层职责

| 层 | 拦什么 | 位置 |
| --- | --- | --- |
| 类型 / Lint | 低级错误、风格漂移 | `开发者入口/测试与检查命令.md` |
| 单元 | 逻辑错误、边界、异常分支 | `测试分层.md` |
| 集成 | 契约不一致、事务 / 并发问题 | 同上 |
| 评审 | 设计缺陷、安全、可维护性 | `.agents/skills/代码审查与风险检查` |
| E2E | 真实用户路径断裂 | `端到端测试.md` |
| 冒烟 | "基本盘"不可用 | `冒烟测试.md` |
| 回归 | 老问题复发 | `回归测试.md` |
| 灰度 / 监控 | 线上真实影响 | `发布与运行/监控与告警.md` |

## 四、风险驱动的投入

| 改动风险 | 判定 | 测试要求 |
| --- | --- | --- |
| 高 | 数据 / 安全 / 契约破坏 / 支付 | 单元 + 集成 + E2E + 安全/性能验证 + 双人评审 |
| 中 | 业务逻辑 / 新功能 | 单元 + 集成 + 关键路径 E2E |
| 低 | 文案 / 样式 / 内部重构 | 单元 + 手工验证（重构须有覆盖测试保护） |

## 五、专项验证

| 专项 | 何时 | 位置 |
| --- | --- | --- |
| 性能基准 | 性能敏感改动 | `性能基准/` |
| 安全验证 | 涉及鉴权 / 输入 / 数据 | `安全验证/` |
| 跨平台 | 涉及桌面端 / 路径 | `端到端测试.md` |
| 数据迁移 | Schema / 回填 | `模块与契约/数据/` |

## 六、质量红线（不可发布）

- 冒烟不过
- 回归中"关键"用例不过
- 安全验证有未解决高危项
- 数据迁移无 rollback 实测

> 需突破红线时，必须获用户书面同意并记录风险（见 `.agents/rules/开发原则.md` 豁免流程）。
