# 性能与可靠性分析

## 何时使用

- 接到"系统变慢了""内存涨了""偶尔超时"这类问题。
- 发布前的容量 / 稳定性评估。
- 评估某个改动对性能的影响。
- 制定或修订 SLO。

## 前置

- 必读 `.agents/rules/可观测性规则.md`、`架构边界.md`。
- 必读 `发布与运行/指标与SLO.md`、`容量与性能.md`。
- 明确**目标指标**（延迟 P50/P95/P99、吞吐、错误率、资源占用、恢复时间）。

## 输入

- 监控面板 / 压测报告 / profile 数据
- 相关代码路径
- 历史基线（`测试与验证/性能基准/`）

## 步骤

1. **定义衡量口径**：指标名、单位、统计窗口、采集方式。没有基线就先建基线。
2. **建立基线**：在**当前版本**上测一遍（压测 / profile / trace），记录原始数据。
3. **定位瓶颈**（依次排除）：
   - 应用层：算法复杂度、N+1、锁竞争、序列化开销、GC 压力；
   - 数据层：慢查询、缺索引、大事务、连接池耗尽；
   - 网络 / IO：往返次数、大 payload、同步阻塞；
   - 资源：CPU、内存、磁盘、连接数、线程 / 协程数。
4. **量化影响**：每个瓶颈给出"贡献占比"的估算，避免优化错地方。
5. **提出方案**：按 **收益 / 成本 / 风险** 排序，优先"低风险高收益"。每个方案写：
   - 改动点、预期收益、验证方法、可能副作用。
6. **可靠性视角**（并行检查）：
   - 单点故障、依赖超时与重试、熔断降级、幂等、限流、背压、故障恢复；
   - 关键路径是否"一个慢依赖拖垮全局"。
7. **更新 SLO**：如基线变化，修订 `发布与运行/指标与SLO.md` 并说明理由。
8. **验证**：优化后用同一口径复测，对比基线，记录提升幅度。

## 输出

- 分析报告（可写入 `发布与运行/容量与性能.md` 或 `变更/<id>/`）
- 更新的 `测试与验证/性能基准/` 基线数据
- SLO / 告警阈值修订建议（落 `发布与运行/监控与告警.md`、`指标与SLO.md`）

## 检查清单

- [ ] 有明确的指标口径与基线数据。
- [ ] 瓶颈结论有数据支撑（profile / trace / 压测），不是"感觉"。
- [ ] 优化方案按收益/成本/风险排序，并给出验证方法。
- [ ] 检查了可靠性风险（超时、重试、熔断、限流、单点）。
- [ ] 优化后做了复测对比。
- [ ] SLO / 告警阈值已同步更新。

## 边界与禁止

- **禁止**在没有基线的前提下声称"性能提升了"。
- **禁止**用"改个缓存就好了"这类无依据结论。
- **禁止**在生产环境直接做压测（除非有隔离方案与批准）。
- 优化不得以牺牲正确性 / 数据一致性为代价；如必须取舍，**写 ADR 并请用户确认**。
