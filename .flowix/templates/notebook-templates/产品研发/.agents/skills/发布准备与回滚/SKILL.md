# 发布准备与回滚

## 何时使用

- 变更已通过验证，准备上线。
- 紧急热修（可精简，但**回滚方案不可省**）。
- 配置 / Feature Flag / 环境变更需要发版配合。

## 前置

- 必读 `.agents/rules/发布与回滚规则.md`、`安全与隐私规则.md`。
- 必读 `发布与运行/发布清单.md`、`环境说明.md`、`发布与运行/回滚手册/`。
- 已有 `验证记录.md` 且结论为"可发布 / 有条件发布"。

## 输入

- `变更/<id>/验证记录.md`、`实现计划.md`（回滚策略）
- 代码 diff / 版本号 / 制品
- `发布与运行/Feature Flag与灰度.md`

## 步骤

1. **确认前置**：验证通过？审查通过？契约已同步？迁移脚本已 dry-run？
2. **写发布计划**：
   - 版本号 / 制品标识、目标环境、发布时间窗；
   - **发布顺序**（例：先迁移 → 再后端 → 再前端 → 最后开 Flag）；
   - 灰度策略：白名单 / 比例 / 地域，放量节奏与观察指标；
   - **回滚方案**：触发条件、回滚步骤、回滚后数据处理（关键！）；
   - 责任人 / 通知对象。
3. **执行前快照**：备份 / 记录当前版本与配置，便于回退。
4. **执行发布**：按顺序操作，逐项打勾，**每步后验证健康指标**。
5. **观察窗口**：发布后按 `监控与告警.md` 观察错误率、延迟、业务指标至少一个观察窗。
6. **判定**：
   - 正常 → 完成放量，写发布记录；
   - 异常 → 按回滚方案执行，记录事件（必要时转 `线上事件诊断与复盘`）。
7. **记录**：在 `发布与运行/发布记录/` 写一条记录（版本、时间、内容、结果、异常与处置）。

## 输出

- `变更/<id>/发布计划.md`（模板：`.agents/templates/变更/发布计划.md`）
- `发布与运行/发布记录/YYYY-MM-DD-<版本>-发布记录.md`
- 更新的 `发布与运行/回滚手册/`、`Feature Flag与灰度.md`、`监控与告警.md`

## 检查清单

- [ ] 验证与审查均已通过。
- [ ] 发布顺序明确，含迁移与 Flag 时序。
- [ ] 回滚方案具体到可执行步骤，且**已验证过可行**。
- [ ] 有灰度与放量节奏。
- [ ] 有观察窗口与明确的回滚触发条件。
- [ ] 发布前已做版本 / 配置快照。
- [ ] 发布记录已写入（含异常与处置）。

## 边界与禁止

- **禁止**在没有回滚方案的情况下发布。
- **禁止**不可逆变更（删表、删数据、破坏性迁移）在无双重确认下执行 —— **必须先获用户明确确认**。
- **禁止**"发布完就完事"，不做观察窗口。
- 热修也要写发布记录；"太急"不是省记录的理由。
