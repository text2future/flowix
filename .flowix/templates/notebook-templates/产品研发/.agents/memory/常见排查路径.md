# 常见排查路径

> **性质**：长期记忆。记录**怎么一步步查**——"遇到 X 现象，按 Y 顺序查"。
> 与 `.agents/context/常见故障与排查.md` 的分工：那份记**已知故障模式**（现象 / 原因 / 止血）；本文件记**可操作的排查手法**。

## 一、使用方式

- 按"现象"归类，每条给出**有序排查路径**与**每步的判据**。
- 新的成功排查案例 → 追加一条。
- 某条路径被做成脚本 / 诊断页 → 更新该条为"直接用工具"。
- 同一路径用超过 3 次 → 考虑做成 Runbook（`.agents/templates/Runbook.md`）。

## 二、条目格式

### P-NN · <现象描述>

```
1. <第一步>
   ├─ <分支 A> → <处理>
   └─ <分支 B> → 继续
2. <第二步>
3. <第三步>
```

**判据**：<达到什么状态才算定位成功>

## 三、排查路径

> 从 P-01 开始追加。下面是一条**填写示例**，请替换为真实内容。

### P-01 · <示例：接口报错但日志里看不到明显异常>

```
1. 用请求 ID 在全链路日志中检索，确认请求是否真的到达服务端
   ├─ 没到 → 查网关 / 负载均衡 / DNS / TLS
   └─ 到了 → 继续
2. 查该请求的完整日志（含 WARN 与框架内部日志）
3. 查是否有异常被 try/catch 吞掉（没有记录）
4. 查外部依赖调用（超时？被熔断？）
5. 本地用同样参数复现，看调用栈
```

**判据**：能定位到具体代码行或具体依赖失败，才算查出来。

## 四、工具与入口速查

| 目的 | 工具 / 位置 |
| --- | --- |
| 串起一次请求 | `x-request-id` / trace_id |
