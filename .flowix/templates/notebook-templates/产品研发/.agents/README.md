# .agents/ — 代理资产总览

本目录是**产品研发工作区的"AI 协作大脑"**。它把人的工程约定和 AI 的执行能力分开摆放，各司其职：

```
.agents/
├── skills/      技能：每个技能只做一件事（怎么做）
├── rules/       规则：硬约束，不可违反（必须怎样）
├── context/     上下文：代码与系统的真实事实（现在是什么样）
├── templates/   模板：产出物的骨架（写字用的格子）
└── memory/      记忆：长期积累的经验（踩过的坑）
```

## 一、五者关系（一句话版）

> **context 描述现实 → rules 划定边界 → skills 执行动作 → templates 规定产出 → memory 沉淀经验。**

任何一次协作的正确顺序：**读 context（现状）→ 守 rules（约束）→ 用 skill（动作）→ 按 template（产出）→ 写 memory（经验）。**

## 四、rules/ 索引（硬约束）

`开发原则` · `代码规范` · `架构边界` · `API与兼容性规则` · `数据与迁移规则` · `测试规则` · `安全与隐私规则` · `可观测性规则` · `Git与PR规则` · `发布与回滚规则`

冲突处理：规则之间冲突时按 `.agents/rules/开发原则.md` 第四节的总优先级（安全 > 数据 > 兼容性 > 测试 > 发布 > 可观测性 > 架构边界 > 代码规范 > Git > 风格）；仍无法判断则**停下来问用户**。

## 五、context/ 索引（事实）

`代码地图` · `模块边界` · `领域模型` · `技术栈与本地环境` · `API与事件契约` · `数据模型与存储` · `外部依赖与集成` · `运行架构` · `常见故障与排查`

> **维护纪律**：代码变了但 `context/` 没更新 = 上下文已过期。变更收敛时（`代码与规格收敛` 技能）必须回写受影响条目。

## 六、使用建议

- **不要跳过 rules**：AI 在被要求写码前，应先声明读了哪些规则。
- **不要臆测 context**：以真实代码为准，发现不一致先修正 context。
- **template 是骨架不是枷锁**：允许增删小节，但**不得删掉"影响与风险""回滚"这类安全小节**。
- **memory 要精简**：只写"下次还能用到"的经验，不写流水账。
