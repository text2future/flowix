# 测试规则（硬约束）

> 测试不是"验证一下而已"，它是**变更可发布的前提**。

## 一、最低要求

1. **新功能必须有测试**；修改逻辑必须有对应测试更新。
2. **缺陷修复必须先有会失败的测试**，修复后转绿（防回归）。
3. 涉及数据 / 契约 / 安全的改动，测试要求**升级**（见下）。
4. **禁止**合入"测试待补"的代码——要么补，要么登记技术债并获批准。

## 二、分层与配比（按 `测试与验证/测试分层.md`）

| 层级 | 职责 | 关注 |
| --- | --- | --- |
| 单元 | 核心逻辑、边界、异常分支 | 快、稳、独立 |
| 集成 | 模块间、DB、外部依赖 | 契约、事务 |
| 端到端 | 关键用户路径 | 真实闭环 |
| 手工 / 探索 | 体验、跨平台、UI 细节 | 发现"没想到的" |

原则：**底层多而快，上层少而真**。不要求覆盖率数字，但**核心逻辑必须有单元测试**。

## 三、必须覆盖的场景

- 正常路径（happy path）
- 边界值（空、0、负、最大、超长）
- 异常路径（错误输入、依赖失败、超时）
- 权限（无权限 / 越权）
- 并发 / 重复提交 / 竞态（如涉及）
- 数据迁移与回滚（如涉及）

## 四、测试质量约束

- 测试必须**独立**：不依赖执行顺序、不共享可变状态。
- 测试必须**可重复**：同样输入同样结果（时间 / 随机 / 网络要可控）。
- 测试**测行为不测实现**：重构不应导致测试大面积失败。
- **禁止**用 `sleep` 等待异步（用轮询 / 事件 / fake timer）。
- **禁止**为了让测试通过而放宽断言。
- **禁止**跳过（skip / xfail）而不写明原因与跟踪项。

## 五、测试数据

- 使用**合成 / 脱敏**数据；**禁止**用生产真实数据（见 `数据与迁移规则.md`）。
- 测试数据必须可**一键重建**（脚本化，不靠手工准备）。
- 涉及时间 / ID 的测试必须**固定**，不能依赖"当前时间"。

## 六、结果诚信

- 未执行的测试**必须**写"未执行"，**禁止**推断、编造结果。
- 失败项**必须**如实记录，禁止隐藏。
- 报告必须包含：命令、结果、证据（日志 / 截图路径）。

## 七、发布门槛

- 冒烟测试**必须全过**才可发布。
- 回归测试中标注"关键"的用例**必须全过**。
- 性能 / 安全测试（如本次涉及）必须有结论。
- 任一门槛不过 → **不可发布**（除非用户明确接受风险并记录）。
