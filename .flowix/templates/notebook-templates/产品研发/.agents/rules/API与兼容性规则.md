# API 与兼容性规则（硬约束）

> 核心命题：**已经发出去的东西，不能随便改坏。** 兼容性成本远低于破坏成本。

## 一、兼容性铁律

1. **向后兼容优先**：新增字段 / 新增端点 / 放宽校验 = 安全；删字段 / 改类型 / 改语义 = 破坏。
2. 破坏性变更**必须**走版本化或过渡期，二者选一，不允许"直接改"。
3. 客户端必须**容忍未知字段**（服务端加字段不应弄坏老客户端）。
4. 服务端必须**容忍新增可选字段的缺失**（前端未升级不应报错）。

## 二、版本策略

- **新增**：不需要版本。
- **兼容性变更**（加字段、加可选参数、加枚举值）：
  - 需评估**客户端枚举处理**是否会崩（未知枚举值是最常见坑）。
- **破坏性变更**：
  - 首选新增版本（`/v2` 或版本头）；
  - 或走"扩展 → 双写 / 双读 → 灰度迁移 → 下线旧版"；
  - **必须**写明弃用时间表与通知方式。

## 三、接口设计约束

- 命名与既有风格一致；资源用复数名词；动作用 HTTP 语义（谨慎发明动词）。
- **幂等性必须显式说明**：`GET/PUT/DELETE` 默认幂等，`POST` 需说明是否幂等及如何保证（幂等键）。
- 分页、排序、过滤参数风格全库统一（见 `模块与契约/API/API目录.md`）。
- 时间统一 UTC + ISO 8601；金额统一最小单位整数 + 币种；**禁止**用浮点表示金额。
- 错误响应结构统一，错误码自 `模块与契约/后端/错误码与异常约定.md` 取，**禁止散装字符串**。

## 四、认证与授权

- 所有非公开端点必须鉴权；权限校验在**服务端**，客户端校验只是体验优化。
- **禁止**把权限判断交给前端。
- Token / 密钥不得出现在 URL query 中。

## 五、事件 / Webhook 契约

- 事件必须有：名称、版本、payload schema、发生时间、唯一 ID。
- 投递语义必须写明（至少一次 / 精确一次）；消费者**必须幂等**。
- 必须定义重试策略与死信处理。
- 事件 schema 变更遵循本文件兼容性铁律。

## 六、外部集成

- 第三方 API 调用必须有：超时、重试（带退避）、熔断、错误兜底。
- 第三方不可用时系统应**降级**而非整体崩溃。
- 第三方密钥走 `发布与运行/配置与密钥管理.md` 的机制，**禁止硬编码**。

## 七、契约文档同步

- 每个 API / 事件变更**必须同步**更新 `模块与契约/API/` 与 `.agents/context/API与事件契约.md`。
- 契约文档与代码不一致 = 视为缺陷，按 `缺陷定位与修复` 处理。
