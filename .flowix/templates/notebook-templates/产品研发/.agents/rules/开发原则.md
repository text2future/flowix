# 开发原则（硬约束）

> 本文件是整个 `.agents/rules/` 的**总纲**。其余规则文件是其展开。冲突时的优先级见文末。

## 一、十条开发原则

1. **先理解，后修改。** 未读 `.agents/context/` 与相关代码前，不得动手改。禁止"猜着改"。
2. **变更为单位。** 任何实现都挂在 `变更/<id>/` 下，先有计划再写码。
3. **小步可提交、可回滚。** 一个提交只做一件事；大改动拆成可独立回滚的步骤。
4. **契约先行。** 涉及跨模块 / 前后端 / 数据结构的改动，先定契约再各自实现。
5. **以代码为准。** 文档与代码冲突时，以代码为事实，并**修正文档**（不是反过来掩盖）。
6. **默认保守。** 拿不准时选可逆、影响小、可灰度的方案。
7. **不夹带。** 修复 bug 不做顺手重构；重构不做功能变更。
8. **可观测。** 关键路径必须有日志 / 指标；新增失败模式必须有可定位线索。
9. **留痕。** 决策写 ADR，经验写 `.agents/memory/`，过程写 `变更/`。
10. **不确定就问。** 涉及不可逆操作（删数据、破坏性迁移、生产直接改）必须先获用户确认。

## 二、不可逆操作清单（动之前必须确认）

| 操作 | 为什么危险 | 必须 |
| --- | --- | --- |
| 删除 / 清空生产数据、表、索引 | 不可恢复 | 备份 + 用户书面确认 + 分批 |
| 破坏性 Schema 迁移（丢字段 / 改类型） | 老数据可能不可读 | 双写 / 过渡期 + 回滚脚本 |
| 强制推送覆盖共享分支 | 他人工作丢失 | 禁止；仅限个人分支且已确认 |
| 直接改生产配置 / 绕过发布流程 | 无记录、难回滚 | 走发布流程 + 记录 |
| 轮换 / 删除密钥 | 可能全站中断 | 排期 + 双密钥过渡 |

## 三、AI 协作特有要求

- 动手前**声明**：读了哪些 `.agents/rules/` 与 `.agents/context/` 条目。
- 不得以"已完成"描述未验证的事；未执行的必须写"未执行"。
- 不得编造测试结果、日志、监控数据。
- 遇到规则冲突，**停下来问用户**，不要自行折中后继续。

## 四、规则优先级（冲突时）

> **安全与隐私 > 数据与迁移 > API 与兼容性 > 测试 > 发布与回滚 > 可观测性 > 架构边界 > 代码规范 > Git 与 PR > 风格**

即：宁可牺牲性能与风格，也不牺牲安全与数据正确性。

## 五、豁免流程

任何对上述规则的违反都必须：
1. 在 `变更/<id>/` 中写明**为什么必须违反**；
2. 得到负责人 / 用户**明确同意**；
3. 记入 `架构决策/技术债务.md` 并给出偿还计划。

**"没时间"不是豁免理由。**
