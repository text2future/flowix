# 安全与隐私规则（硬约束）

> 本文件优先级**最高**。与其他规则冲突时，以本文件为准。

## 一、密钥与凭据

- **禁止**硬编码任何密钥、token、密码、私钥到代码 / 配置 / 日志 / 提交历史。
- 密钥统一走环境变量 / 密钥管理服务（见 `发布与运行/配置与密钥管理.md`）。
- `.env` 必须被 `.gitignore` 忽略；只提交 `.env.example`（无真实值）。
- 密钥必须**可轮换**；轮换要有过渡期（双密钥），避免全站中断。
- **禁止**把密钥写进 URL query、错误信息、日志。

## 二、鉴权与授权

- 权限校验**必须**在服务端进行；前端判断仅作体验。
- 每个敏感端点必须显式声明所需权限；**默认拒绝**（deny by default）。
- **必须**防越权：检查资源归属（不能只校验"已登录"）。
- 桌面端 IPC 通道必须白名单化 + 权限校验（见 `模块与契约/桌面端与本地能力/`）。

## 三、输入与输出

- **所有**外部输入（请求、文件、命令行、IPC、第三方回调）必须校验与转义。
- **禁止**拼接 SQL / shell / 路径；使用参数化 / 白名单。
- 文件路径必须防目录穿越（`../`）；上传文件必须校验类型与大小。
- 输出到 HTML 必须转义，防 XSS；外部请求必须限制目标，防 SSRF。
- 反序列化不可信数据必须受限（禁用危险类型 / 限制大小）。

## 四、数据与隐私

- **最小化采集**：只采业务必需的数据。
- 个人敏感数据必须**加密存储**（传输必须 TLS）。
- 日志 / 错误 / 监控中**禁止**出现：密码、token、身份证号、银行卡、完整手机号等。
  - 需要标识时用**哈希 / 掩码**。
- 访问敏感数据必须有**审计记录**。
- **禁止**把生产数据复制到测试 / 本地（用脱敏 / 合成）。
- 用户删除请求必须真正删除或不可逆匿名化，并在承诺期限内完成。

## 五、依赖与供应链

- 新增依赖必须检查：维护活跃度、已知漏洞、许可证兼容。
- 必须定期扫描依赖漏洞（CI 中集成）。
- **禁止**引入来源不明的二进制 / 脚本。

## 六、安全事件响应

发现以下情况**立即**升级（并在 `SECURITY.md` 记录）：
- 密钥泄露（**立刻轮换**，先止血）；
- 未授权访问 / 越权漏洞；
- 个人数据泄露；
- 依赖严重漏洞被利用。

流程：**止血 → 评估影响面 → 通知用户 → 修复 → 复盘 → 防回归。**

## 七、红线

- 涉及安全的改动**必须**过安全评审（`@org/security`）。
- **禁止**为"方便调试"临时关闭鉴权 / 校验并提交。
- **禁止**在未获授权的情况下测试他人系统 / 扫描外部目标。
- 安全测试必须**在授权范围与隔离环境**内进行。
