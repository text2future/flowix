# 缺陷队列

> **所有缺陷的唯一登记处。** 每条从登记到关闭的全生命周期在此跟踪。
> 详情写成独立文件：`进行中缺陷/BUG-NNN-<slug>.md`（模板见 `.agents/templates/缺陷/`）。

## 一、严重级别

| 级别 | 定义 | 响应时限 |
| --- | --- | --- |
| **P0** | 崩溃 / 数据损坏 / 安全事件 | 立即 |
| **P1** | 主流程不可用 | 当日 |
| **P2** | 功能受损但有绕过 | 本迭代 |
| **P3** | 轻微 / 体验问题 | 排期 |

## 二、状态流转

```
待复现 → 定位中 → 修复中 → 待验证 → 已修复 → 已关闭
   └──────────────────────────► 已拒绝 / 不修复（必须写理由）
```

## 三、缺陷清单

| ID | 标题 | 级别 | 状态 | 发现方式 | 影响版本 | 负责人 | 关联 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

> 计数提醒：未关闭 **P0/P1 > 0** 时应优先处理，暂停非关键发布。

## 四、处理流程

```
1. 登记（本表 + 建 BUG-NNN 文件）      6. 补防回归测试（修复前必须为红）
2. 定级（严重级别）                    7. 验证（原路径 + 相邻路径）
3. 复现（或标注"待复现"）              8. 更新状态 + 归档到 已修复缺陷/
4. 定位根因（.agents/skills/缺陷定位与修复）  9. 可复用经验 → memory/经验与陷阱.md
5. 最小修复（不夹带重构）
```

## 五、注意事项

| 事项 | 要求 |
| --- | --- |
| 无法复现 | **仍要登记**，标注"待复现"并保留线索 |
| 修复夹带重构 | **禁止**，拆独立变更 |
| 用 try/catch 吞异常 | **禁止**作为最终修复 |
| 数据损坏类 | **立即**升级，评估是否需数据修复（`模块与契约/数据/数据修复规范.md`） |
| 修复后 | 必须补防回归测试并登记到 `测试与验证/回归测试.md` |

## 六、与变更的关系

| 情况 | 处理 |
| --- | --- |
| 修复涉及较大改动 | 建 `变更/CHG-xxx/` 走完整流程 |
| 小改动 | 仅用 `BUG-NNN` 跟踪，走简化流程 |
| 根因是设计问题 | 写 ADR 或记入 `架构决策/技术债务.md` |
