# 提交与 PR 流程

> 规则以 `.agents/rules/Git与PR规则.md` 为准，本文件讲**怎么做**。

## 一、分支

| 分支 | 用途 |
| --- | --- |
| 主干 | 始终可发布 |
| `feature/<变更号>-<简述>` | 变更开发 |
| `fix/<缺陷号>-<简述>` | 缺陷修复 |
| `hotfix/<描述>` | 线上紧急修复 |

> 分支名带编号，便于追溯"为什么有这次改动"。

## 二、提交

| 项 | 要求 |
| --- | --- |
| 粒度 | 一个提交一件事，**可独立回滚** |
| 信息 | 说明**为什么**改，而非复述改了什么 |
| 关联 | 关联变更 / 缺陷编号 |
| **禁止** | 夹带无关改动、格式化整个仓库、提交密钥与本地配置 |

## 三、PR 要求

| 项 | 要求 |
| --- | --- |
| 关联 | 变更 `CHG-xxx` 或缺陷 `BUG-xxx` |
| 描述 | 改了什么 / 为什么 / **怎么验证的** / 怎么回滚 |
| 规模 | 尽量小；大改动拆多个 PR |
| 检查 | CI 全绿 |
| 评审 | 至少 1 人；涉及契约 / 数据 / 安全时**按 `CODEOWNERS` 指定的人必须过** |

## 四、合并

| 项 | 要求 |
| --- | --- |
| 前置 | CI 绿 + 评审通过 + 无未解决评论 |
| 方式 | 按仓库约定（通常保留可追溯历史） |
| 合并后 | 更新变更的 `任务与进度.md` / 缺陷状态 |

## 五、评审关注什么（给评审者）

1. **正确性**：有没有边界与异常分支漏掉
2. **安全性**：输入是否校验、权限是否在服务端判定
3. **兼容性**：契约 / 数据迁移是否安全
4. **可维护性**：命名、边界、是否夹带重构
5. **可验证**：是否有测试能证明它对

> 详细清单见 `.agents/skills/代码审查与风险检查/SKILL.md`。

## 六、紧急修复（hotfix）

```
1. 先止血（回滚 / 关开关），再修
2. 最小改动，不夹带
3. 可简化评审流程，但**不可省**回滚方案与事后复盘
4. 事后补正式修复 + 防回归用例
```
