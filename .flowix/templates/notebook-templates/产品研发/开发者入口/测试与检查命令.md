# 测试与检查命令

> 提交前、PR 时、发布前**分别要跑什么**。策略见 `测试与验证/测试策略.md`。

## 一、按阶段

| 阶段 | 跑什么 | 要求 |
| --- | --- | --- |
| 提交前 | 类型检查 + Lint + 相关单元测试 | 必须全过 |
| 开 PR 时 | 单元 + 集成（CI 自动） | 必须全过 |
| 合并前 | 关键端到端（`@critical`） | 必须全过 |
| 发布前 | 冒烟 + 回归关键用例 | 必须全过 |

## 二、命令

| 目的 | 命令 | 耗时 |
| --- | --- | --- |
| 类型检查 | `<cmd>` | 秒级 |
| Lint | `<cmd>` | 秒级 |
| 单元 | `<cmd>` | 秒级 |
| 集成 | `<cmd>` | 分钟级 |
| 端到端 | `<cmd>` | 分钟级 |
| 冒烟 | `<cmd>` | 分钟级 |
| 回归 | `<cmd>` | 分钟级 |
| 只跑某文件 | `<cmd> -t "<名>"` | — |
| 检测 flaky | `<cmd> --repeat-each=3` | — |

## 三、检查失败怎么办

| 情况 | 处理 |
| --- | --- |
| 类型 / Lint 报错 | **直接修**，不要 `--no-verify` 绕过 |
| 测试失败且与本次改动相关 | 修代码，不是改测试 |
| 测试失败但确实无关 | 确认后记录，**不要**删测试 |
| flaky | 修或按规则降级，**禁止**重跑直到绿 |

> **红线**：**禁止**为了通过检查而放宽规则、跳过用例、屏蔽告警。需要例外时走 `.agents/rules/开发原则.md` 的豁免流程。

## 四、维护规则

- 命令变化 → 同步本文件与 `常用命令.md`。
- 新增测试层 → 补进第一节的对应阶段。
