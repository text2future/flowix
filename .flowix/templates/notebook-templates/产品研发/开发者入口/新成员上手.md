# 新成员上手

> **第一天**：能跑起来。**第一周**：能独立完成一个小改动。**第一个月**：能参与评审。

## 一、第一天

| # | 事项 |
| --- | --- |
| 1 | 读 `README.md`（本仓库是什么、怎么组织） |
| 2 | 读 `AGENTS.md`（协作方式与规则优先） |
| 3 | 读 `.agents/context/` 全部（事实层，建立地图） |
| 4 | 读 `.agents/rules/开发原则.md`（规则优先级） |
| 5 | 跑通 `开发者入口/开发环境准备.md` |
| 6 | 完成一次最小主流程 |

## 二、第一周

| # | 事项 |
| --- | --- |
| 1 | 读 `.agents/rules/` 其余规则 |
| 2 | 读 `.agents/context/代码地图.md` + `模块与契约/` 关键文件 |
| 3 | 领一个小任务（可从文档修正 / 小缺陷开始） |
| 4 | 走完整流程：变更 → 实现 → 验证 → 评审 → 合并 |
| 5 | 读 `.agents/memory/经验与陷阱.md`（避免重复踩坑） |

## 三、必读清单（按重要性）

| 顺序 | 文件 | 为什么 |
| --- | --- | --- |
| 1 | `README.md` | 知道这是什么 |
| 2 | `.agents/rules/开发原则.md` | 知道红线与优先级 |
| 3 | `.agents/context/代码地图.md` | 知道代码在哪 |
| 4 | `.agents/context/模块边界.md` | 知道改动会影响谁 |
| 5 | `.agents/skills/变更实现计划/SKILL.md` | 知道怎么开工 |
| 6 | `发布与运行/发布清单.md` | 知道什么叫"完成" |

## 四、常见困惑

| 困惑 | 答案 |
| --- | --- |
| 文档和代码不一致 | **视为缺陷**，按流程修正 |
| 规则不合理 | **不要**硬绕，走豁免流程或提改进 |
| 不知道改动会影响什么 | 用 `代码库理解与影响分析` 技能 |
| 需求不清楚 | 反查 `产品输入/`；仍有歧义就问产品 |

## 五、维护规则

- 新人卡住的地方 → **必须**回写本文件或相应文档。
- 上手时间明显变长 → 说明工程或文档退化了，当成问题修。
