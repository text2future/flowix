# 发布流程

> 怎么把改动放出去。规则见 `.agents/rules/发布与回滚规则.md`，清单见 `发布与运行/发布清单.md`。

## 一、发布前

```
1. 变更状态为"可发布"（验证关键项全过，未执行项已如实标注）
2. 走完 发布与运行/发布清单.md 全部确认项
3. 回滚方案已实测
4. 观察指标与告警就绪（且对应 Runbook 已存在）
```

## 二、发布步骤

| # | 步骤 | 说明 |
| --- | --- | --- |
| 1 | 构建产物 | 记录版本号与提交号 |
| 2 | 部署 / 分发 | 按开关或比例 |
| 3 | 冒烟验证 | 失败即回滚，不"再看看" |
| 4 | 开始观察 | 记录开始时间 |
| 5 | 逐步放量 | 每步看指标再放大 |
| 6 | 全量 | 确认稳定后 |
| 7 | 记录 | 建 `发布与运行/发布记录/` 条目 |

## 三、发布中出问题

| 情况 | 动作 |
| --- | --- |
| 冒烟失败 | **立即回滚**，定位后再发 |
| 指标异常 | 关开关 / 回滚，**不要**边观察边等 |
| 数据异常 | 立即停止写入 → 评估影响 → 走数据修复规范 |

> **判断原则**：可疑就先退回去。回滚成本远低于一次事故。

## 四、发布后

| 项 | 要求 |
| --- | --- |
| 观察窗口 | 覆盖一个业务周期 |
| 指标核对 | 与发布前基线对比 |
| 清理 | 全量后清理发布型 Flag |
| 收敛 | 更新 `变更/<CHG>/任务与进度.md` 与 `收敛记录.md` |

## 五、维护规则

- 流程与工具变化 → 更新本文件。
- 每次发布问题 → 复盘并检查"是清单缺项还是执行不到位"。
