# 技术债务

> 记录**有意识地欠下的债**，并给出偿还计划，避免债务隐形累积。
> **原则**：技术债不是"以后再说"，而是**有意识、有记录、有计划**的妥协。
>
> 与相邻概念的区别：**已知限制**（`事件与问题/已知限制.md`）不打算改；**未解决技术问题**（`.agents/memory/未解决技术问题.md`）还没解法；本文件 = 已有方案，等偿还。

## 一、债务看板

| ID | 标题 | 类别 | 严重度 | 状态 | 引入 | 建议偿还时机 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

> **类别**：架构 / 代码 / 测试 / 文档 / 依赖 / 性能 / 安全。
> **严重度标准**：高 = 影响稳定性 / 安全 / 数据；中 = 影响效率 / 体验；低 = 影响整洁。
> **健康度参考**：高严重度未处理项 > 3 条 → 建议在排期中预留偿还时间。

## 三、管理规则

| 规则 | 说明 |
| --- | --- |
| 引入必须有理由 | 写清取舍，不是"以后优化" |
| 必须登记 | 未登记的债务 = 隐形炸弹 |
| 必须有偿还时机 | 或明确标注"已接受"（不还） |
| 定期回顾 | 每迭代检查一次，调整优先级 |

## 四、偿还节奏

| 情况 | 建议 |
| --- | --- |
| 高严重度未处理 > 0 | 立即排期 |
| 中严重度 | 每 2–3 个迭代处理 1–2 条 |
| 低严重度 | 随相关变更顺手处理 |
