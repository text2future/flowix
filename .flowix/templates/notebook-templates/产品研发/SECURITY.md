# 安全策略（SECURITY）

## 一、报告安全问题
- 发现安全漏洞请**不要**公开提交 issue。
- 通过私下渠道联系安全负责人：<security@example.com>。
- 提供：影响范围、复现步骤、可能的修复建议。

## 二、响应流程
| 阶段 | 目标时限 |
| --- | --- |
| 确认收到 | 1 个工作日 |
| 初步评估 | 3 个工作日 |
| 修复 / 缓解 | 视严重度（高危优先 hotfix） |

## 三、安全开发要求（详见 `.agents/rules/安全与隐私规则.md`）
- 不在代码 / 日志 / 提交中泄露密钥与个人数据。
- 所有外部输入视为不可信，做校验与转义。
- 鉴权 / 授权默认拒绝（deny by default）。
- 依赖定期扫描，高危漏洞限期修复（见 `架构决策/依赖升级计划.md`）。

## 四、密钥管理
- 密钥通过环境变量 / 密钥管理系统注入，不入库。
- 见 `发布与运行/配置与密钥管理.md`。

## 五、泄露处置
- 一旦密钥泄露：立即轮换 → 排查影响范围 → 记录到 `事件与问题/线上事件/` → 复盘。
