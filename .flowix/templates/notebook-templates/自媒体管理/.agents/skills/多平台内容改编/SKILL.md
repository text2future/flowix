# 多平台内容改编

## 触发条件
- 内容包主稿完成，需要产出各平台版本。
- 上游就绪：`内容/<状态>/<slug>/内容卡片.md` 与主稿。

## 输入
- 内容卡片与主稿
- `平台规范/<平台>.md`（该平台的调性、篇幅、形式、规则）
- `账号策略/品牌声音与表达规范.md`（保持调性一致）

## 输出
- `内容/<状态>/<slug>/<平台>-<类型>.md`（如 `小红书-笔记.md`、`B站-脚本.md`、`抖音-口播稿.md`）
- 在内容卡片中登记已完成 / 待完成的平台版本

## 工作流
1. 读目标平台规范，明确形式（图文 / 口播 / 视频脚本）与约束（字数、尺寸、话题）。
2. 保留核心信息，重写开头钩子与结构以适配平台。
3. 标题、标签 / 话题、封面文案按平台最佳实践产出。
4. 登记到内容卡片；不改动主稿核心事实。

## 质量检查清单
- [ ] 每个平台版本都对照了该平台规范
- [ ] 核心信息一致，形式按平台调整（非直接搬运）
- [ ] 标题 / 话题 / 封面文案已适配
- [ ] 品牌声音保持一致
- [ ] 内容卡片已更新版本状态

## 上游 / 下游
- 上游：`内容包创建`
- 下游：`发布准备与检查`
