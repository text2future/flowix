## 推进本主题

本主题流程：规则设计 → 数据与权限 → 功能开发 → 迁移测试 → 上线观察。

1. **规则设计**：明确等级、积分、权益有效期和扣减规则，列出边界情况。
2. **数据与权限**：核对历史会员字段与角色权限，约定映射和异常处理。
3. **功能开发**：实现查询与兑换等功能，保持界面反馈和实际扣减一致。
4. **迁移测试**：先迁测试批次，核对数量、权益差异与重复记录，修正后复跑。
5. **上线观察**：确认上线与回退条件，观察兑换异常和客服工单。

- 任务入口：`进度视图.csv`。按事项ID查找记录，展示给用户时使用任务名称。
- 决策与依据：`业务规则/计划表.csv`、`业务规则/资料/资料清单.csv`。
- 新任务：复制 `公共/权益功能单.md`，在 `功能与权限/` 下用可读的任务名称建目录；场次、批次等重复任务加日期。
- 填写案例与真实任务时沿用空白模板的标题和字段，不另造一套简化结构。字段不适用写明原因；资料缺失时说明缺口及影响。过程写已发生的动作，产物保存到任务目录并登记实际路径。
- 结果写入 `数据/会员迁移.csv`，沿用同一事项ID。检查字段单位、时间范围和对象粒度；单次任务不填项目累计数。缺失值不得用0代替。
- 本主题完成条件：历史权益、迁移数据和用户通知核对。先逐项核对模板中的审核字段，再更新状态；缺少影响验收的证据时保持待确认。

## 本库中的教学记录

`功能与权限/积分兑换权益功能/任务记录.md` 与 `功能与权限/积分兑换权益功能/积分权益验收.md` 展示一次任务的记录及产物。其中人物和数据为模拟；未经用户要求，不把模拟数据当作真实事实或继续虚构实际结果。外部发布、支付和联系按用户授权执行。

数据记录先确认一行代表什么对象、哪段时间与什么单位。原始记录、分类合计和项目汇总分别维护；验收表的期望结果必须与实际结果逐项对应，不能只填写“通过”。
