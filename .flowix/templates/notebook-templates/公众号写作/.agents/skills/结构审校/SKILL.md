# 结构审校

## 触发条件
- `文章.md` 初稿完成，尚未进入排版。
- 用户说「帮我看看结构 / 顺不顺」。

## 输入
- `文章/写作中/<slug>/文章.md`
- 选题陈述（校验是否跑题）

## 输出
- 一份「审校意见」：问题清单 + 具体修改建议（可就地批注或返回给用户）。

## 审查清单
**整体**
- 是否回答了选题承诺的价值？有无跑题？
- 单篇是否只讲一件事？

**结构**
- H2 之间是否层层递进（不是并列堆砌）？
- 每节是否有「论点 → 论据 → 小结」？
- 段落是否过长（移动端 > 5 行需拆）？

**逻辑**
- 转折是否自然？有无跳跃？
- 案例与论点是否一一对应？

**可读性**
- 有无术语未解释（对照术语表）？
- 有无重复、啰嗦、口头禅？

## 工作流程
1. 通读，标注「跑题 / 缺论证 / 结构乱」三类问题。
2. 给出优先级（P0 必改 / P1 建议 / P2 可选）。
3. 输出修改清单，必要时直接修订 `文章.md` 并说明改了哪。

## 质量清单
- [ ] 每个 P0 问题都有明确改法
- [ ] 不擅自改变事实与观点（那是事实核查的活）
- [ ] 修改后不影响原意

## 衔接
- 上游：大纲与写作
- 下游：事实核查
