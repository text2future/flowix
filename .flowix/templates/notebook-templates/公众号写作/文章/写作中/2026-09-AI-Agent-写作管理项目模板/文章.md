# 我用一套 Agent 流水线，把公众号写作从「硬写」变成「组装」

> 摘要：写作最难的从来不是写，而是把灵感、资料、草稿、排版、发布散落各处后还能拼回来。我用 9 个专职 Agent 技能把全流程收敛成一个可复制的笔记空间——本文就是它的第一篇产物。

## 01 开头：你是不是也这样

收藏了一堆「以后要写」的灵感，真要动笔时却找不到；好不容易写了初稿，排版花的时间比写还长；发完一篇，三个月后想互链旧文，翻聊天记录翻到崩溃。

我之前就是这么写的。直到我把公众号写作拆成一条流水线，交给一组专职 Agent 去跑——现在写一篇，我只需要做两件事：**定选题、拍板发布**。中间的脏活，Agent 接了。

## 02 背景：写作的痛不在「写」

我们低估了写作的「非写作成本」：

- **收集无门槛但不成系统**：灵感在备忘录、链接在浏览器、读者问题在后台，三处互不相通。
- **资料与正文脱节**：查到的数据写完就丢，下次从头再来。
- **审校靠肉眼**：结构和事实只能自己硬看，漏了就是社死。
- **发布是另一个项目**：排版、封面、摘要、标签，样样手动。

症结是：**写作不是一个动作，是一条流水线**，而绝大多数人用「一个文档」去装整条线。

## 03 核心方法：9 个技能跑一条线

我把流水线拆成 9 个专职 Agent 技能，每个只做一件事，产物是上下游的交接棒：


| 环节  | 技能      | 它产出什么           |
| --- | ------- | --------------- |
| 收集  | 灵感整理    | 结构化选题卡          |
| 决策  | 选题评估    | 五维打分 + go/no-go |
| 论据  | 资料研究    | 资料与备注.md        |
| 起草  | 大纲与写作   | 文章.md 初稿        |
| 结构  | 结构审校    | 修改清单            |
| 事实  | 事实核查    | 核查报告            |
| 排版  | 公众号排版   | 微信友好版           |
| 发布  | 发布准备    | 终检 + 摘要 + 封面    |
| 长尾  | 旧文检索与更新 | 互链 + 常青巡检       |


关键不是「用 AI 写」，而是**给 AI 一个它看得懂的仓库**：固定的目录、固定的模板、固定的规范。Agent 才知道东西放哪、下一步找谁。

## 04 实操：一篇是怎么「组装」出来的

以本文为例，真实路径是这样的：

1. 灵感丢进 `收件箱/灵感/`，「灵感整理」提炼成选题卡写进 `选题池.md`。
2. 「选题评估」打分 20 分（价值5 需求4 差异4 可行4 时效3），go，建 `文章/写作中/2026-09-AI-Agent-写作管理项目模板/`。
3. 「资料研究」把我想讲的点拆成子命题，填进 `资料与备注.md`，标出证据缺口。
4. 「大纲与写作」套用「项目发布」模板，先给大纲确认，再成文。
5. 「结构审校」挑出两处跑题，「事实核查」核对了文中的所有数字。
6. 「公众号排版」加序号、分段、补文末三模块。
7. 「发布准备」跑终检清单，出摘要和标签。
8. 发布后，「旧文检索与更新」自动找相关旧文做往期回顾。

我全程没碰过排版按钮。

## 05 常见误区

- **误区一：让 AI 一口气写完。** 没有上游资料和中游审校，出来的东西漂亮但空。流水线贵在「分段把关」。
- **误区二：目录越自由越好。** 越自由，Agent 越不会用。固定的 `YYYY-MM-<slug>/` 才是协作的契约。
- **误区三：发了就不管。** 旧文是资产，常青内容定期刷新，长尾流量很可观。

## 06 结尾：你也能搭一套

这套系统的全部文件——目录结构、9 个技能、6 个模板、规范文档——我都整理成了可复制的项目模板。你照着建，半小时就能跑起来。

写作系统不会替你想观点，但它会让你**把精力只花在观点上**。这事儿，值。
