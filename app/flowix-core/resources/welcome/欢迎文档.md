# ++flowix 让 Agent 背后的文档库可管理、可修正++

AI Agent 的表现，往往取决于它背后那份看不见的文档库。

它可能读过一篇过时的资料，忽略了一条关键规则，也可能因为缺少必要的上下文而反复犯错。你看见的是它的回答，却不容易看见它究竟依据什么做出判断。

flowix 把这份隐藏的上下文带到前台。它以文档库为核心，让你能浏览 Agent 所依赖的资料和规则，审阅它产出的结果，并在发现问题后回到文档中修正。

于是，使用 Agent 不再只是反复调试对话，而是持续改进它工作的依据。

---

## 1. 产品理念

在多数 Agent 客户端中，文档库藏在会话背后。Agent 读取了哪些资料、遵循了哪些规则、遗漏了哪些上下文，用户往往并不清楚；当它出错时，也很难判断问题究竟出在哪里。

flowix 把这份隐藏的上下文带到前台。它以文档库为核心，让你能像整理项目资料一样，浏览 Agent 所依赖的笔记、规则和输出；也能在发现问题后，直接修改资料、调整规则，让下一次任务更可靠。

flowix 不只是让 AI 读取文档，而是让你理解并掌控 AI 工作的依据。

> ### 它解决的问题
>
> - **不知道 Agent 依据什么工作**：不清楚它读取了哪些资料、遵循的规则。
> - **上下文分散**：资料、Prompt、规则和工作流散落在不同位置，难以整理和更新。
> - **出错后难以溯源**：当 Agent 输出不理想时，难以定位原因，也无法修正它的工作方式。
>
> flowix 让你从反复试错，转向持续改进 Agent 的工作依据。

## 2. 快速上手

### 2.1 创建与管理笔记本

笔记本是一个本地文件夹，笔记则是其中的 Markdown 文档。创建笔记本时，可以使用默认的“文稿”位置，也可以自定义保存位置。

- **文件树与笔记列表**：文件树（访问空间）用于管理全部文档，包括 Markdown 笔记、Word 文档、图片等；笔记列表用于管理当前笔记本中的全部 Markdown 笔记。
- **默认新建位置**：可指定在“笔记列表”模式下新建笔记时使用的目标文件夹。
- **视图**：在文件树模式下，可为笔记或非笔记资料创建管理视图，便于按不同维度浏览与检索。
- **置顶**：任意笔记、视图或资料文件均可置顶，作为高频入口使用。

### 2.2 使用 AI 功能

可按需选择以下三种接入方式。使用前，请完成相应客户端或模型服务的安装、登录与配置。

- **使用本地客户端**：接入本地安装的 ChatGPT、Claude Code、OpenCode 等客户端进行对话。使用 Deepseek Harness 客户端时，请先在偏好设置中安装 flowix 连接插件。
- **使用 flowix AI + 自定义模型**：配置模型服务后，可通过文档模式或代码模式处理任务。当前暂不支持联网搜索，以及图片、视频生成；具体能力以所用版本为准。
- **使用第三方 Agent 客户端**：将笔记本所在文件夹作为项目打开，或通过 CLI / MCP 连接文档库，让 Agent 读取、检索和更新内容。使用前需完成对应的连接配置。

### 2.3 初始化 AI 知识库

向 Agent 说明目标，让它根据实际需求搭建目录结构与协作规则。可参考以下提示词：

```plaintext
我的核心需求是：[一句话目标]

请在当前笔记本初始化一份 AI 文档库：
- 设计满足目标所需的最小目录结构。
- 创建 AGENTS.md，写明目录用途、工作方式和维护规则。
- 仅在确有需要时创建或导入技能，并存放于 .agents/skills/。
- 保留已有内容，避免覆盖或重复创建。
- 只创建必要内容，并说明如何开始使用。
```

### 2.4 笔记管理

- **标签管理**：在正文中使用 #idea  #meeting  #todo  #prompt  #agent 等标签标记文档。
- **视图管理**：通过多维表格、日历、看板和画廊浏览、管理笔记。
- **笔记属性**：为笔记添加来源、评分、地点、优先级等属性；可先在设置中创建预设属性，再为笔记填写相应值。

## 3. 使用场景

以下目录结构仅为可按需调整的参考示例，并非 flowix 的固定要求。

### ==3.1 个人 AI 知识库==<!-- flowix:text {"bg":"purple","fg":"purple"} -->

将书籍、论文、课程和日常记录整理为结构化文档库，让 Agent 在回答、写作和研究时引用可追溯的资料。

你可以随时检查来源、修正结论，并将 Agent 的输出回写至文档。知识库会随使用不断更新，成为可复查、可编辑、可复用的工作依据。

```plaintext
我的笔记本/
├── 资料库/            ← 原始素材，只读不改
├── wiki/             ← LLM 维护的知识层
│   ├── index.md      ← 总索引
│   ├── log.md        ← 变更日志
│   ├── concepts/     ← 概念页
│   ├── entities/     ← 实体页
│   ├── sources/      ← 来源摘要
│   └── synthesis/    ← 综合分析
├── 生成内容/          ← 生成的输出物
└── AGENTS.md         ← 知识库结构与维护规则
```

### ==3.2 文档工作台：小红书运营工作台==<!-- flowix:text {"bg":"purple","fg":"purple"} -->

将账号定位、用户洞察、选题规则、内容资产和数据复盘集中管理，让 Agent 基于同一套上下文完成选题、创作和复盘。

Agent 负责选题、资料整理、初稿、封面提示词、发布检查和数据复盘；人负责定位、审美、关键判断和最终发布。每一篇笔记的数据与评论，都会成为下一轮选题与创作的依据。

```plaintext
小红书工作台/
├── 账号/
│   ├── 定位.md          ← 账号定位、目标人群、差异化
│   └── 品牌声音.md       ← 语气、禁用表达、人设边界
├── 市场/
│   ├── 趋势/            ← 热点、搜索词、平台话题
│   ├── 对标/            ← 对标账号与爆款拆解
│   └── 用户画像/         ← 用户画像、评论洞察、高频问题
├── 选题方向/
│   ├── 选题池.md         ← 选题库与优先级
│   └── 打分规则.md       ← 选题打分规则
├── 内容生产/
│   ├── 草稿/            ← AI 初稿
│   ├── 定稿/            ← 人工定稿
│   ├── 已发布/           ← 已发布笔记与最终版本
│   ├── 图片视频资产/      ← 封面、图片、视频脚本
│   └── 日历.md          ← 内容日历
├── 数据复盘/
│   ├── 小红书笔记/       ← 每篇笔记数据
│   ├── 周报.md          ← 周度复盘
│   └── 爆款范式.md       ← 可复用的爆款规律
└── AGENTS.md           ← Agent 的角色、规则与工作流
```

### ==3.3 产品开发：规格驱动开发（SDD / Vibe Coding）==<!-- flowix:text {"bg":"purple","fg":"purple"} -->

将需求、验收标准、技术方案、接口契约和任务清单沉淀为结构化文档，让 Agent 按规则生成方案与代码。

你可以在关键节点审查规格与实现差异，减少返工和不可控输出，让开发过程可追踪、可复用。

```plaintext
我的产品/
├── .specify/
│   ├── constitution.md       ← 项目技术栈、规范、安全原则
│   └── templates/            ← spec、plan、tasks 模板
├── specs/
│   └── 001-user-auth/
│       ├── spec.md           ← 需求与验收标准
│       ├── clarifications.md ← 澄清记录
│       ├── plan.md           ← 架构与技术方案
│       ├── data-model.md     ← 实体、字段、迁移
│       ├── contracts/        ← API / 事件 / 接口契约
│       ├── research.md       ← 技术调研与备选方案
│       ├── checklist.md      ← 上线前检查项
│       └── tasks.md          ← 可执行任务清单
├── tests/
└── AGENTS.md                 ← Agent 的角色、边界和工作规则
```

在产品开发场景中，可通过侧边栏的“仓库”管理多个代码仓库。

## 4. 约定文件与目录

根据所用 Agent 及工作流的约定，文档库可能包含以下文件与目录：

- **AGENTS.md**：向支持该约定的 Agent 说明项目背景、目录结构、工作方式与维护规则。
- **.agents/skills/**：存放可复用的 Agent 技能。

这些文件与目录承载着 Agent 的运行规则、能力定义和项目上下文。可建议根据需求变化持续维护其中的规则。
