flowix 是 ==AI Agents 的文档空间==<!-- flowix:text {"bg":null,"fg":"blue"} -->。它常用于解决使用 AI Agent 时遇到的以下问题：

- Prompt 指令散乱在各处，缺乏管理
- AI Agent 总是在某些地方踩坑犯错，记忆断片
- 通过对话跑通的工作流，不知道该怎么沉淀

flowix 可以让 AI 总结工作流、常见问题、个人偏好等内容，并沉淀下来反复使用。

同时，个人日常记录也可以成为高质量的输入信息。

---

## 1. 产品理念

在 Agent 客户端中，文档库是项目和会话背后的隐藏信息，flowix 则将文档库作为第一公民，并进行会话管理。

从文档库出发进行管理，方便直观地围绕文档，编写工作流，让写作、研究、整理和 AI Agent 任务都从同一份资料出发。

同时，flowix 的笔记本与 Agent 的项目是互通的，产品追求文档库在多产品复用。

## 2. 快速上手

### 2.1 创建、管理笔记本

笔记本是一个本地文件夹，笔记则是其中的 Markdown 文档。创建笔记本时，可以使用默认的本地“文稿”位置，也可以自定义保存位置。

- 文件树和笔记列表：文件树（访问空间）管理全部文档（Markdown 笔记、Word、图片等），笔记列表则管理笔记本的全部 Markdown 笔记。
- 笔记默认新建位置：指定在“笔记列表”模式中新建笔记时使用的目标文件夹。
- 视图：文件树模式下，可以针对笔记、非笔记（资料）创建管理视图，通过视图更方便阅读浏览。
- 置顶：文件树模式下，任意笔记、视图、资料文件都可置顶作为入口使用。

### 2.2 使用 AI 功能

可以按需选择以下三种接入方式。使用前，请完成相应客户端或模型服务所需的安装、登录与配置。

1. **使用本地客户端**：本地安装的 ChatGPT、Claude Code、OpenCode 可用于对话。使用 Deepseek Harness 客户端时，请先在偏好设置中安装 flowix 连接插件。
2. **使用 flowix AI + 自定义模型**：配置模型服务后，可使用文档模式或代码模式处理任务。当前接入暂不支持联网搜索及图片、视频生成，具体能力以所用版本为准。
3. **使用第三方 Agent 客户端**：将笔记本所在文件夹作为项目打开，或通过 CLI / MCP 连接文档库，让 Agent 读取、检索和更新内容。使用 CLI / MCP 前，需先完成对应的连接配置。

### 2.3 初始化 AI 知识库

向 Agent 说明目标，再让它按实际需求搭建目录和规则。可以使用以下提示词：

```plaintext
我的核心需求是：[一句话目标]
请在当前笔记本初始化一份 AI 文档库：
- 设计满足目标所需的最小目录结构。
- 创建 AGENTS.md，写明目录用途、工作方式和维护规则。
- 仅在确有需要时创建或导入技能，并存放于 .agents/skills/。
- 保留已有内容，避免覆盖或重复创建。
- 只创建必要内容，并说明如何开始使用。
```

### 2.4 笔记管理

- 标签管理方案：直接写在正文里，例如 #idea、 #meeting、 #todo、 #prompt、 #agent。flowix 会自动识别提取。
- 视图管理：通过多维表格、日历、看板、画廊进行笔记管理浏览。
- 笔记属性：为笔记添加如来源、评分、地点、优先级等属性信息，可先在设置中创建预设属性，再为笔记填写相应的值。

## 3. 使用场景

以下目录树是可按需调整的参考结构，并非 flowix 的固定要求。

### 3.1 个人 AI 知识库

可以写读书笔记、旅行路书、工作日报和日常随笔，支持日常记录、资料整理与知识积累。

可把需求、资料、参考链接写进文档，让 Agent 基于内容进行总结、改写、问答，也可以进一步拆解任务、编写代码等。Agent 的输出也可写回到文档里，形成可以复查、继续编辑和再次调用的记忆，让 AI 协作逐步形成可积累的知识系统。

例如，可以参考下面的 Karpathy 风格知识库结构，整理书籍、论文和课程：

```
我的笔记本/
├── 资料库/            ← 原始素材，只读不改
├── wiki/             ← LLM 维护的知识层
│   ├── index.md      ← 总索引
│   ├── log.md        ← 变更日志
│   ├── concepts/     ← 概念页
│   ├── entities/     ← 实体页
│   ├── sources/      ← 来源摘要
│   └── synthesis/    ← 综合分析
├── 生成内容/          ← 生成的输出物
└── AGENTS.md         ← 知识库结构与维护规则
```

### 3.2 文档工作台（例如：小红书运营工作台）

把小红书运营从“每次找 AI 写一篇笔记”升级为一个持续运转的内容操作系统，这样每一篇笔记的数据和评论，都会变成下一轮选题与创作的输入，形成可积累的运营记忆。

- Agent 负责选题、资料整理、初稿、封面提示词、发布检查和数据复盘；
- 人负责定位、审美、关键判断和最终发布。

```
小红书工作台/
├── 账号/
│   ├── 定位.md          ← 账号定位、目标人群、差异化
│   └── 品牌声音.md       ← 语气、禁用表达、人设边界
├── 市场/
│   ├── 趋势/            ← 热点、搜索词、平台话题
│   ├── 对标/            ← 对标账号与爆款拆解
│   └── 用户画像/         ← 用户画像、评论洞察、高频问题
├── 选题方向/
│   ├── 选题池.md         ← 选题库与优先级
│   └── 打分规则.md       ← 选题打分规则
├── 内容生产/
│   ├── 草稿/            ← AI 初稿
│   ├── 定稿/            ← 人工定稿
│   ├── 已发布/           ← 已发布笔记与最终版本
│   ├── 图片视频资产/      ← 封面、图片、视频脚本
│   └── 日历.md          ← 内容日历
├── 数据复盘/
│   ├── 小红书笔记/       ← 每篇笔记数据
│   ├── 周报.md          ← 周度复盘
│   └── 爆款范式.md       ← 可复用的爆款规律
└── AGENTS.md           ← Agent 的角色、规则与工作流
```

### 3.3 产品开发：规格驱动开发（SDD / Vibe Coding）

把软件开发从“直接让 AI 写代码”升级为规格驱动开发（Spec-Driven Development, SDD）：先写清楚要做什么、为什么做、验收标准是什么，再由 Agent 生成技术方案、任务清单、代码和测试；人则在关键节点审查规格、方案和差异。

```plaintext
我的产品/
├── .specify/
│   ├── constitution.md       ← 项目技术栈、规范、安全原则
│   └── templates/            ← spec、plan、tasks 模板
├── specs/
│   └── 001-user-auth/
│       ├── spec.md           ← 需求与验收标准
│       ├── clarifications.md ← 澄清记录
│       ├── plan.md           ← 架构与技术方案
│       ├── data-model.md     ← 实体、字段、迁移
│       ├── contracts/        ← API / 事件 / 接口契约
│       ├── research.md       ← 技术调研与备选方案
│       ├── checklist.md      ← 上线前检查项
│       └── tasks.md          ← 可执行任务清单
├── tests/
└── AGENTS.md                 ← Agent 的角色、边界和工作规则
```

产品开发时，可通过侧边栏的“仓库”管理多个代码仓库。

## 4. 约定文件与目录

根据所用 Agent 和工作流的约定，文档库中可能包含以下文件与目录：

- `AGENTS.md`：向支持该约定的 Agent 说明项目背景、目录结构、工作方式与维护规则。
- `.agents/skills/`：存放可复用的 Agent 技能，是否自动加载取决于所用客户端及其配置。

这些文件与目录承载着 Agent 的运行规则、能力定义和项目上下文。修改前应了解其用途；删除或改变结构可能影响相关 Agent 或工作流。你可以随着需求变化持续维护其中的规则。
